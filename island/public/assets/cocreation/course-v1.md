# Hyper Dimension · OPC 共创课程 v1
版本：V201 / 150分钟 / 当前版本课程试运行稿

## 课程成果

一份1–6项挑战的 .hdpack.json；一条提交与审核记录；一份服务器确认的实际试玩成绩；v1/v2版本切换与回退记录。挑战使用当前25类功能建筑及308份配方中的关联内容，复用像素与折纸素材。本课不导入任意代码、新配方、模型调用或外部图片。联机服务支持独立岛主账户；工坊内审核者仍是作品所在小岛的岛主，跨账户投稿审核平台尚未接入。

## 开课前

使用公开的 Agent 源码包和完整素材，在每台授课机器上提前完成部署。教师的 .env.local、data、运行记录和私人文档留在原机器；共创练习不需要 DeepSeek 密钥。.hdpack.json 是内容包，完整游戏仍需单独部署。

推荐 Node.js 24、Python 3.11。Windows 在完整游戏目录执行下面的命令；macOS 将 `--python=python` 换为 `--python=python3`。已经部署且正在运行的副本先核对版本和端口，避免重复启动。

```sh
node tools/agent-deploy.mjs plan
node tools/agent-deploy.mjs doctor --python=python
node tools/agent-deploy.mjs setup --python=python --offline
node tools/agent-deploy.mjs verify
node tools/cocreation-check.mjs
node tools/agent-deploy.mjs run --mode=lan
```

浏览器打开 `http://127.0.0.1:4175/`，使用启动终端显示的加入码注册自己的岛主账户，回到小岛后进入「后台 → 共创工坊」。账号、作品和版本保存在本机服务。每位学员可使用自己机器上的副本；共用授课服务器时各自登录不同账户。课堂之间交换导出的内容包，接收方在自己的工坊导入副本并审核，不需要传递账户或整个 data 目录。

像素与折纸是同一小岛的外观。切换后使用同一作品书架、版本与成绩，无需重复导入。每个小岛的工坊最多24件作品，每件最多20个历史版本；给每位学员的作品使用不同编号。

## 150分钟授课流程

| 时间 | 教师演示 | 学员操作 | 必须检查的成果 |
| --- | --- | --- | --- |
| 0–15分钟 | 试玩风铃茶屋的配对关卡，观察目标与反馈 | 记录一个失败原因和一条有用提示 | 学员能解释目标与操作 |
| 15–35分钟 | 从潮汐茶席模板新建，介绍作者、编号和内容授权 | 改标题、作者、介绍并保存草稿 | 本机共创书架出现自创作品 |
| 35–65分钟 | 说明建筑/图纸绑定、关卡种子、三档难度与品质目标 | 更换种子，写3条具体提示；目标先设75 | 草稿校验通过，说明符合建筑 |
| 65–90分钟 | 演示双画风和完整JSON最多6项挑战 | 查看像素/折纸资源，导出并交叉阅读说明 | 作者、授权、两套说明、编号均正确 |
| 90–115分钟 | 提交冻结、审核说明、启用、实际试玩 | 配对完成后保存共创成绩；失败可重试 | 审核版本摘要、成绩、作者一致 |
| 115–135分钟 | 编辑下一版，审核启用v2，回退v1 | 改进一条提示或难度并完整操作 | v1仍可导出与重新启用，历史未丢失 |
| 135–150分钟 | 展示书架与成绩，明确课后边界 | 导出最终包，说明下一次改进 | 作品JSON和版本/成绩截图完整 |

## 教师讲解要点

种子固定本局内容，改变种子才更换关卡；难度固定于审核版本，试玩中不能擅改。品质目标55–95，不是任意奖励倍率。目标通过「关卡完成且品质达标」判断，分数从操作重放得到。共创试玩不扣材料、不送物品/岛币，也不计正式制作成就；「前往正式制作」使用游戏原配方、解锁和结算。

茶席模板：先观察，再翻相同茶材，错误消耗次数；不要求盲目高速点击。陶艺模板：修齐12段器型，按分区上釉，完成升温/保温/退火；用它示范「操作提示必须针对过程」。陶艺课堂宜先使用轻松难度，手工试玩需留足时间。

首次课程请另一位实际学员阅读说明并试玩，作者记录对方的卡点，再修改作品。交换的 JSON 在接收方小岛形成一份独立副本；工坊的审核按钮不代表远程教师已经审核了作者的原件。全包内容包括作者填写的说明与参数；CC-BY/CC0仅涉及这些内容，不转授基础游戏代码或岛内美术版权。没有自定义素材导入器，不把已有岛内图片写成学生原创。

## 验收与故障恢复

- 草稿、提交、审核、启用四步均有记录；不能直接启用草稿。
- 学员真实完成一次试玩；脚本验证不能替代人的课堂验收。
- 关闭练习后重新打开，保留同一运行、种子和已确认操作。服务每5秒保存；突然杀掉页面可能丢失最后一批尚未确认输入，不会伪造已确认成绩。
- 断网出现「待核对」时，保留页面，使用「核对上次操作」。同一请求只登记一次；不可删除待核对记录后随意重复提交。
- 另一窗口修改版本时，保留草稿、刷新工坊再提交；同时写入需通过服务器版本核对。
- 明确「结束本局」生成结束记录；不会获得物品。过期练习只能结束并重开。
- 导出v1，启用v2再回退v1，检查标题、提示、关卡种子及作者。
- 同一账户切换双画风再打开工坊，核对作品编号、启用版本与成绩保持一致；清空浏览器缓存后重新登录，再从服务恢复。

## 记录一次真实试讲

每位学员记录开始/结束时间、第一次达标的用时与尝试次数、最难找到的按钮、最有帮助的提示，以及一条修改建议。教师保留匿名人数、完成率、主要卡点和下一轮修改清单。没有真实学员或尚未完成试玩时，相关项保持「未验证」，不以自动脚本或模型代签。

## 课程边界与后续

本课是声明式挑战共创；小游戏仍为演示原型，会继续优化。独立岛主账户、联机会客与 A2A 已有功能入口，这门课聚焦作品设计与版本迭代，不将一次课堂练习记作完整联机或现实 Agent 任务验收。新增配方/素材/动作、NPC脚本、跨账户生态投稿平台及跨岛课程内容结算仍待补齐。2–3小时课程的人类试讲与理解度尚未验收。ESP32实体与商业部署不在本轮范围。
