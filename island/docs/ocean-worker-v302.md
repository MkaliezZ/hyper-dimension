# V302 · 海面后台渲染与交互响应

Intel Mac 的玩家动作检查中，34.6 秒 CPU 采样里，`drawOceanShader` 自身占用约 14.7 秒，含子调用约 14.9 秒。同期居民连续作业检查也出现失败，并记录到明显偏低的原生帧计数。原始失败与诊断均保留；没有扩大玩家动作、招聘或居民工作的验收时限。

海面 GPU 编译、海岸距离纹理上传、着色和完成等待现在进入独立 Worker。着色器常量、海岸计算和完整画布分辨率保持不变。实际 GPU 完成后才交出位图；最多保留一个进行中的绘制和一个最新请求，旧镜头、旧主题、旧尺寸的帧不会遮到当前地图。替换、丢失、失败与退出时释放位图。无可用 GPU 或上下文丢失时保留原有二维波浪，真实上下文恢复后重新绘制。

招聘正在筹备或发送邀请时保留弹窗后的地图画面，避免重复背景绘制挤占输入与存档回执；世界时钟、人物逻辑和服务端事务不变。窗口尺寸变化仍会重绘，等待结束后恢复正常地图绘制。

Node 22.13.0 与 25.8.1 的 1518 项默认规则通过。48 组原生画面比较逐像素一致，新增主线程 WebGL 上下文为零。双画风玩家动作、招聘、连续居民任务，以及共享时令、真实 Worker GPU 丢失/恢复和二维兼容回退检查通过。居民任务仍使用首项 120 秒、后续共享 240 秒的原工作时段预算。全部来自隔离的虚构岛屿，本轮没有模型调用或游戏时钟加速。

托管 Mac 的玩家、招聘及居民检查仍需在该修复提交上重新确认。最终源码包的独立安装与持续运行、实际 OPC 课程及真人验收也继续保留各自边界。[机器可读范围](verification-v302.json)。README 不记录这些 CI 流水。
