# V282 · 登船验证顺序与 Mac 进程符号诊断

## 登船检查

旧测试将多名游客的请求直接送到存档服务，两次请求可能读取同一个版本；实际客户端的 `saves.action` 会串行提交。原 Intel Mac 的折纸登船检查出现 `save_conflict`。

在保留原断言的隔离对照中，把登船和另一位游客下船的提交分别延迟 200 / 30 毫秒，复现了同一旧版本被并发使用的冲突。测试适配器现在按实际客户端顺序派发，并在检查错误前等待该场景的全部命令；同样延迟条件下原五个场景全部通过，关联九项检查通过。没有调整游戏逻辑、收入、物资、时长或原断言。

## Mac 现场

ARM 居民任务和生产售卖的旧失败均已保留测试自有渲染器／GPU 进程采样。新增手动 `Island Mac stack symbols` 诊断，只读取指定运行的产物，使用 [Chromium 官方协议](https://chromium.googlesource.com/chromium/src/+/main/tools/mac/download_symbols.py) 中的版本／架构地址读取调试符号，校验框架 UUID，再用系统工具解析样本地址。输出只包含小型诊断报告和解析后的文本；不会启动游戏、改动进度或代替验收。

六项本地保护检查通过；三个已有进程样本的版本、UUID、加载地址与相对偏移已解析。实际 Mac 符号解析与冻结根因仍待确认。没有通过切换窗口、修改浏览器渲染参数、放宽时限或删减断言来宣称修复。

管家立绘选择失败过去未进入上传范围；现在保留该测试报告、失败截图及有限的个人操作请求元数据，原选择／持久化／裁切断言及超时不变。没有记录认证、完整保存请求或用户资料。
