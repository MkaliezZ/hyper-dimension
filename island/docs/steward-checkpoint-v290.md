# V290 · 管家手动消息的持久化检查点

## 修复

管家寄出消息前使用现有的队列检查点。它等待更早的工作并保存用户消息、待确认请求，再发起本轮委托；之后加入的后台工作可以继续运行。

此前额外等待整个保存队列空闲。只要后台不断补入工作，这个等待就会一直追随新的队尾，用户看到“等候回复”，实际请求却尚未寄出。修复移除这次额外的全队列空闲等待，保留原检查点和小岛／画风变更检查。

## 证据

- 两种画风使用真实隔离存档与备份服务，给每次备份增加声明的 80ms 服务延迟，连续补入后续备份。
- 修复前，四秒观察窗口内后台已完成 23–24 次备份，两种画风均没有寄出手动请求。
- 修复后，后台保持运行，手动消息约 0.5–0.6 秒寄出。外部请求开始前，实际服务端存档已经包含用户消息、待确认答复及其请求编号，更早的备份已经完成；后续备份继续进行。
- 新原生组件回归两例通过，原四秒时限和上述持久化断言保留。32项存档、命令预留、数据核验及重试规则通过，无跳过或取消。
