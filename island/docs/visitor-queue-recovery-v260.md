# V260 · 恢复存档后的候船位占用

恢复游客时，已走完行程的游客会立即选择返程候船位。旧流程按存档顺序逐人恢复，此时排在后面的游客已经保存的候船位尚未登记，可能被前面的游客再次选择。服务端正确拒绝重复占位，客户端重新读取后又按同一顺序恢复，形成重复的 409 请求。

现分两步恢复：先登记所有游客及其已保存的候船位，再恢复每人的路线和上下船流程。满员时继续等待空位，受邀伙伴的候船位也参与避让。服务端的占位保护、登船时间、游客消费、资源预留与经济规则均未改变。

双画风十项复现检查在旧实现全部失败，修复后通过；相关游客规则23项与完整1386项规则通过。使用实际从零经营折纸岛的出错存档副本，保留两位已评价游客和一位夹在中间的已结束行程游客，三人经实际道路和渡船分别离岛，共30467毫秒，未超原150秒预算，存档接口、页面和素材均无错误。集市历史及真实招聘交付、付款记录保持原样。

原始经营记录完成了12笔集市交易、单次77岛币奖励和伙伴离岛，但曾出现546次候船位错误，原报告仍保留为失败。此次修复与隔离续行不会抹除该历史，也不代表全渠道长期经济、真人或物理多设备验收。候选包和完整联机验证继续推进。见[证据范围](verification/v260/visitor-queue-recovery.json)。
