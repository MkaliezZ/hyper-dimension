# V323 · 编辑政策时的招聘提示恢复

## 已修复

招聘面板原先为了保护正在输入的政策草稿，直接跳过全部重绘；这也让联网状态错误无法更新。现在状态提示独立更新，表单的原 DOM、焦点和未提交内容继续保留。错误文字通过 textContent 显示。

这是已确认的“政策输入框保持焦点”故障。旧 Windows 托管案例中另一次未确认焦点的 409 提示超时，仍不据此宣称根因已解决。

## 验证

- V322 原版在像素和折纸两种外观均复现：真实成功状态读取已返回，错误提示在原 8 秒内仍不消失。候选两种外观通过。
- 原生界面依次经历一次错误、恢复、保持编辑时再次错误及再次恢复。原 8 秒门保留；同一个输入框、焦点和草稿“37”保持，未提交政策、未请求聘用，100 岛币与预留保持。
- 原 V222 的 409／503、唯一预留、请求身份、取消及回执门四例通过，没有放宽断言或时限。
- 相关 21 项规则在 Node 22、25 各通过，包括实际交付后支付 8 岛币、去重、预算下限、失效邀约、原地续约和跨岛档案。

较早的 V75／V76 检查通过普通存档直接修改筹备状态，当前受保护服务正确拒绝这些写入。本次将准备、绑定、续约和作业改为正式服务端事务；改变工作量的负例也通过实际居民交付产生。保留原结果断言，服务端权限规则不变。这九项重新纳入默认规则。

第一轮组合检查保留为失败：旧夹具 7 项失败，且初始化报错前未关闭自有服务。修复夹具初始化清理后继续验证；准备状态、权限开关和证据目录的迭代错误也保留。它们没有被覆盖为“首次通过”。
