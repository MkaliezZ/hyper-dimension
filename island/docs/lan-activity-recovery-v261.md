# V261 · 联机小游戏的中断续玩与成绩提交

关卡暂停保存后，服务端可能已经接收一批输入，浏览器却没有收到回执。旧入口会直接恢复关卡，再把旧批次回执用于清理新输入队列，造成画面通关而服务端仍未通关。领取回调提前返回或提交失败时，还可能被小游戏误当成已接受，关掉可重试的结果。

继续挑战前，现在先按原请求编号核对已保存回执，再用确认后的关卡状态建立新的输入队列。领取会等待当前请求结束，检查账号、活动和关卡编号，提交剩余输入，并复用已有的同一笔成绩请求。重复点击共享同一次完成流程；失败明确返回未接受，保留重试能力。服务端输入回放、真实时间限制、入场预留、奖励与费用规则均未改动。

新增 `npm run test:activity-recovery-native` 定向回归。两种画风均经过真实浏览器操作：暂停、丢弃服务端已接受的回执、刷新后直接继续、完成小游戏、提交成绩并执行付费结算。每种画风均为品质100，原批次与原关卡编号保持，成绩只提交一次；结算重复请求不再发奖，双方合计只扣8岛币场地费，携带木材只转交一次，预留全部释放。完整1386项规则通过。

测试使用两个虚构账号及明确的初始100岛币、会场材料和服装；只有准备等待沿用61000毫秒的测试时钟偏移，小游戏按实际时间回放。每次只渲染一位访客视图，未调用模型。这不等于四岛、随行居民、真实原机管家A2A整段或真人验收；这些仍在继续。旧四账号失败、旧回归夹具和断言字段误读记录保留，没有改写为通过。见[证据范围](verification/v261/lan-activity-recovery.json)。
