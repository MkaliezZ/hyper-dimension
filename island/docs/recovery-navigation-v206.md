# 核对后返回小岛的旧页面隔离

V205 的 Windows 托管恢复检查在取消后再次出现 `resource_state_conflict`。核对已经取得新的服务端进度，但 `location.reload()` 只发起导航，不会立即终止旧页面。恢复锁提前解除后，旧动画帧、定时器或离页回调仍持有旧游戏对象，可能重新暂存过时的物资占用；新页面于是再次要求核对。

核对成功后现在持续保持恢复锁，直到旧页面真正退出，不再恢复旧模拟，也不接受旧回调的保存或作业提交。再次点击复用已完成的核对，不重复读取或发起导航。界面保留“进度已核对，正在回岛”的反馈；核对失败仍允许重试，未确认的原始请求仍保留。

新增确定性规则回归：在导航尚未退出时提交旧对象并触发离页，V205 会重新出现旧预留，修正后保持已确认状态。实际浏览器回归将导航延后，并强制执行一次旧页面检查点；使用不可变 V205 客户端复现了与托管检查相同的物资冲突，修正后的像素／折纸页面通过取消、丢失回包、材料、唯一回执和连续刷新检查。

另在 Codex 内置浏览器的独立 localhost 测试岛实际点击“核对进度并返回小岛”，确认页面返回、背包可操作、后续保存正常。测试岛与用户的 127.0.0.1 服务、身份、浏览器存储和存档分开；这项结果不是对用户私人存档或物理多设备的验收。

托管诊断产物补充保留恢复与访客回归的报告、截图。GitHub Actions 失败情况继续单独监测，不在 README 中加入 CI 流水。
