# V255 · 写入占用与已完成锁的恢复

实际Windows文件共享验证复现了两类问题：活动档案／结算日志的原子替换会在短暂占用时中断；存档、联机身份和活动档案的锁清理失败后，后续操作可能一直得到忙碌提示。

活动写入与结算日志复用原有2.5秒有限重试。清理锁时，每次尝试均重新读取并核对当前进程和原随机编号，只删除自己的锁。短暂占用解除即可完成清理；占用超过本次有限等待时，仅在进程内记住这次已经结束的操作，下一次请求可再尝试清理。文件已属于新编号或另一进程时保留它。原活动锁等待、失效进程处理、请求编号和账目规则不变。

两组实际1200／3500毫秒文件占用测试覆盖三种锁、活动当前／前一档案，以及已经扣过场地费后中断的结算日志。资金与原请求恢复后仅有一场活动，合计预留11岛币；持续失败保留原档。锁更换所有者和其他进程的档案不会被删除。活动8项基线失败6项；清锁7项基线失败7项，其中6项是实际功能失败，另1项是新所有权约束。修复后两个有重叠的关联集合各35项、完整1350项规则在本机Windows通过。

结算夹具明确使用已有物资／资金和固定时间；它验证Windows写入与唯一账目，不代表零开局、原生联合活动、实体多设备或真人验收。早期夹具在零金额保护步骤设置占用，没有到达预期扣款边界；原失败记录保留，改到实际场地费步骤后重新验证，未放宽业务断言。
