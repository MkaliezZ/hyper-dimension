# V281 · 已授权玩家动作与并发回执

## 修复

等待居民或其他后台响应时，玩家已开始的采集动作可能停在末帧，完成回调一直得不到执行。现在采集、制作、农田、采矿与派对收尾会绑定实际返回的作业身份。只有与当前服务端活动作业的种类、编号、存档世代、序号和时长一致时，等待中的动画才可结束并向原控制器排队提交完成。

动画结束不会直接发放物资或改写土壤。取消、跨存档、旧作业、NPC 作业和没有服务端许可的本地回调继续保留原有保护；隐藏窗口不补算时间。服务端结算和原来的幂等编号保持不变。

## 已执行验证

- 原应用的等待动画函数对照：旧代码完成回调为 0 次，修复后为 1 次。
- 实际 Windows 隔离游戏服务：旧代码在接受居民响应但暂不交给客户端时，蜂蜡采集停在 1.6 秒末帧；保留原失败。修复后像素、折纸都结束姿态，响应释放前库存和完成回执保持为 0；释放后只提交一次原作业、获得 2 份蜂蜡，刷新后仍为 2。
- 原采矿→林地、农田→林地及刷新再采集流程，两画风通过；原时间预算、库存和可行走返回点断言保留。
- 29 项关联规则及 1,451 项默认检查通过，包括 14 项 Windows 运行目录保护检查。
- V280 主模块恢复的完整双画风原生重新进入验证也已通过。

本机已对照 14 份完全相同的服务端／控制器文件应用客户端补丁，三个端口均核对返回内容；未读取或修改原存档与配置，无服务重启。需要刷新现有页面以载入新脚本。
