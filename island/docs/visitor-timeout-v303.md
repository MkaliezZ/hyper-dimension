# V303 · 游客超时回执与居民任务续做

Windows 托管检查里，折纸风自定义制作任务等待 180 秒仍未完成。隔离记录显示：封蜡前置工序已完成，信件制作进行到 19.116／20 秒；一笔游客结算请求被中止后，存档进入待确认，暂停了模拟逻辑。后续帧循环仍在运行。该次记录没有保留底层异常名称；以原代码和真实 12 秒 fetch 超时进行隔离复现，可重现同类锁定。

现在只对游客游戏事务的 fetch 超时额外核对一次。使用已经持久化的原请求内容、版本、身份和请求 ID，由服务端识别已提交的同一笔事务。每次 fetch 仍为 12 秒、Worker 请求仍为 15 秒。第二次也失败时保留原回执和人工恢复入口。普通断线、明确 HTTP 拒绝、居民与玩家命令、导入、历史恢复及现实 Agent 工作的处理保持原规则。

隔离原生测试先在旧代码下确认两主题均因真实超时失败；修复后均核对成功。实际 HTTP 服务已提交的首次结算响应被保留至 12 秒超时，随后收到字节一致的重试；库存、收益与回执只结算一次，空浏览器重开和独立磁盘实例重放也不增加收益。该故障测试使用声明的初始物资、100 币与预置到服务完成点的模拟时钟，不能作为自然经营时长或从零盈利验收。

Node 22.13.0 和 25.8.1 的 1550 项默认规则通过，包含 32 项新增边界检查。原有双画风自定义居民筹备、玩家动作检查通过，保留 180 秒任务时限、15 秒动作准备时限、正常工作计时与原断言。托管 Windows 恢复仍需新提交的运行确认。
