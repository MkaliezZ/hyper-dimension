# V226 · 存档替换与重新进入 / Save replacement and re-entry

历史恢复、签名存档导入和服务端进度切换共用已确认状态的接续流程。浏览器取消跳转时，旧页面继续保持锁定，不能将替换前的状态写回。自动重试跳转失败后，可点击常驻的“返回小岛”。

## 状态与数据

| 情况 | 行为 |
| --- | --- |
| 历史恢复确认成功 | 保留替换前暂存与服务端备份，接续已确认状态；旧页面保持锁定直到离开。 |
| 恢复请求网络结果不确定 | 持久保留这次替换标记，刷新后不再次发送恢复。用户可读取并选择当前服务端进度；系统不宣称原恢复一定成功。 |
| 导入回执丢失 | 保留并使用原预览编号核对，沿用服务端已有导入去重，不另起导入。 |
| 已确认进度改变了世界身份 | 保留旧页暂存，接续服务端新进度；等待已提交的旧作业回包结束后再完成接续。 |
| 暂存副本写入失败 | 留在核对状态，显示错误；不假称保存成功，也不从旧页继续自动保存。 |

- 接续状态后，先等待较早的缓存捕获完成，再清理旧作业与时钟请求，避免迟到缓存重新留下旧请求。
- 导入和恢复期间阻止新作业、保存和重复替换。恢复结果不确定时，旧作业与时钟请求不会重放进替换后的进度。
- 旧浏览器回执迁入后台暂存时，导入、替换标记先提交后再移除旧键；不清空浏览器或用户数据。
- 历史恢复结果待核对时，较早的导入记录不会优先触发重试；用户选择当前服务端进度后，旧导入回执另存，避免反复要求核对。
- 原服务端权限、签名、钱包、招聘和跨岛任务替换限制保持有效。

## 验证范围

双画风四个有效失败基线已复现，最终六个原生场景通过，包括两种画风各一次丢失恢复回执后刷新、人工选择服务端进度。八项新增规则覆盖旧回包等待、不重放、拒绝、离线后初次创建、世界身份改变、暂存写入失败及旧回执迁移。完整规则 1240 项通过。

原生测试使用隔离的虚拟账号与真实本机 HTTP、签名导出、历史备份和点击操作；只注入一次旧页面迟到暂存，不注入游戏结果或时间。未读取原 Codex 标签页或用户存档，不等同于真人、实体 Mac 或完整产品验收。证明摘要见 [验证记录](verification/v226/save-replacement.json)。

Confirmed replacements keep the outgoing document sealed until navigation. Unknown history-restore outcomes are retained and never blindly resubmitted; selecting server progress adopts the current authoritative state. Imports reuse their existing preview identity. Only isolated automated scenarios are verified here.
