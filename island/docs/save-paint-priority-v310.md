# V310 · 存档准备与画面绘制的调度

Intel Mac 的原生采集检查在原 15 秒准备期限内未能进入所需的并发回执状态。一次失败停在采集授权返回后的前端接续，性能诊断中则已开始授权动作，但无关居民回执还未被测试暂留。诊断保留了原期限和真实接口，不能将这些结果解释为接口未接受操作。

采样的 26.8 秒中，约 6.5 秒落在岛屿绘制调用树，首次创建声音上下文约 1.8 秒；存档 Worker 的多次往返也受到主线程调度影响。这是该托管环境的一次采样，不代表所有设备的性能比例。

修正包括两处：静态采集目录沿用已经绘制的模糊背景，关闭目录或窗口尺寸改变后重新绘制；持久化快照等待绘制机会时，可以让出一次 Canvas 绘制，下一帧必须继续绘制。后者不能连续跳过两帧。模拟更新、已有动作、寻路和时钟仍在每次正常更新中运行，保存完成条件、网络期限、服务端回执及奖励规则均不变。声音功能保留。

本机受控的 2 倍 CPU 节流中，原版本与候选目录修正都通过，未复现 Intel Mac 的原失败。随后完整候选通过了双画风原生采集，以及双画风观察延迟 3 秒的夹具：真实无关居民回执暂留期间，已授权采集动作完成，库存仍等待权威结果；放行后只有一次结束与收益，刷新后数量保持正确。只读绘制计数确认目录背景未重绘、存档绘制让步不连续，原 15 秒准备期限与测试脚本未修改。

新增边界检查覆盖正常绘制、并发快照、不可连续让步、原 100 毫秒 RAF 兜底，以及隐藏窗口、缺少 RAF 和 RAF 抛错后的优先级清理。原有存档顺序、玩家／居民动作与帧循环的相关检查也通过。

V309 的恢复／导入定向检查已在托管 Intel Mac 通过全部六种案例。RAF 中断任务链也在 Windows、Mac ARM、Intel Mac 的双画风通过，均产生三张真实任务回执和必需截图。它们的恢复不代表整个矩阵通过；本次玩家操作调度修正的托管结果仍待确认。[机器可读验证范围](verification-v310.json)。

V309 完整矩阵中的 Windows 商品陈列检查另有新失败：两种画风的 32 像素商品图像检查超过原 5 秒解码期限，尚未进入成交验证。原生日志和隔离产物已保留，定向入口增加真实图片请求的只读时序和 CPU 采样，未改测试断言或期限；该问题仍在诊断。

完整默认规则检查已在 Node 22.13.0 与 25.8.1 各通过 1600 项，无失败或跳过；资格来自隔离目录的本机自动检查，不是托管修正或真人验收。
