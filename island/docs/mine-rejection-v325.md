# V325 · 矿脉占用后的交互恢复

玩家申请开工后，如果服务端明确返回 409／field_occupied，且没有已接受票据、没有其他待核对事务，控制器不再显示全局恢复锁；提示选择其他矿脉。此时没有已开工的作业需要取消，也不发放矿物或改变权限。

超时、其他待核对请求、其他 HTTP 状态、制作和钓鱼继续保留原恢复流程。修复只作用于明确拒绝的采矿开工。

## 证据

原版两画风的真实 DOM 都复现：没有票据、没有待核对请求，仍锁住整个地图。候选 12 个原生界面用例通过，涵盖解锁后选择另一矿脉和五类保护边界。

实际隔离服务通过正式接口预留一份 20 秒 NPC 矿脉作业。测试桥在核对真实版本后调用生产玩家控制器，真实服务端返回 409／field_occupied；玩家没有票据、没有待核对请求，个人矿石没有增加，NPC 预留保持。正式取消测试自己的 NPC 预留后，两画风均通过原来的鼠标采矿和实际获益、林地采集、耕地、室外返回点与刷新恢复检查。没有注入已完成动作、时间或奖励。

这份额外 NPC 预留是明确的占用夹具，不代表 NPC 自然行走的验收。原生场景检查仍保留 12 秒采矿界面门和 12 次尝试上限；只有实际 HTTP 确认的占用拒绝才可重选，而且必须确认控制器已解锁。最终仍必须取得矿石并完成全部原断言。

第一轮实际服务夹具漏传取消预留所需的 expectedVersion，整体按失败保留；修正夹具后继续验证。没有放宽服务器版本规则。

四地图焦点读取、居民完成回执超时和旧 Mac 取消仍是独立未关闭事项。新提交托管、确切归档和真人验收另行记录。
