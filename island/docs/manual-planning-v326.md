# V326 · 手动管家批量分工的排队顺序

## 修复

聊天和已知手动回执恢复携带“用户正在等待”的本地排队信息。批量分工会等待当前事务返回，再优先于尚未开始的后台作业登记；显式存档核对屏障仍需先执行，自动巡查保持原有 FIFO。队列继续交替处理前台与后台任务，避免后台饥饿。

优先级不进入模型输入、正式事务内容或持久回执。已接受但回执不明确的作业保持原请求身份与核对阻塞，不通过重建任务或重复奖励跳过。

## 已验证与边界

- 原 V325 原生浏览器夹具在两画风均复现：手动批量分工被未开始的后台作业挡住；自动登记和核对屏障顺序正确。
- 修正前保留原始报告。夹具最初错误地要求不明确事务的 idle 成功，修正为确认其按 action_pending 阻塞；没有修改正式恢复规则。
- 聚焦规则 16 项通过，包含自动调用限额、排队公平性、核对屏障、原事务保护及手动回执重放身份。
- 候选原生浏览器 8 个用例通过：两画风的手动、自动、屏障和不明确回执；实际 SaveClient Worker、HTTP SaveStore、磁盘重开，零新增资源与游戏币。为隔离排队夹具，不代表完整地图或托管检查恢复。

V325 Windows 托管居民任务曾在初次登记之前超时；本修复证明一项具体排队缺陷，不据此宣称已解释所有托管失败。四地图保留/焦点读取、实际 Windows/macOS 多设备、新玩家与 OPC 试课仍另行验收。普通独立目录中的完整居民动作链已双画风通过（原三步任务、刷新续做、空浏览器重开、三张正式回执及原 120/240 秒工作时限）；1,657 项默认规则通过。确切交付 ZIP 的全新安装结果另记。
