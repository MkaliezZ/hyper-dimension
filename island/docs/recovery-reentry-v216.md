# V216 · 可继续的进度核对与夜间居民规划

## 进度核对

核对开始后，先将当前暂存和原作业编号写入本机浏览器的持久恢复日志，再等待已提交请求。页面分别显示保留副本、等待作业、核对保存回执、核对作业回执和读取服务端进度的步骤。

副本确认写入后，恢复栏提供普通链接“重新进入并继续核对”。这条入口可在原请求等待期间使用。新页面凭本会话、同一岛屿和存档身份的短期确认标记，在模拟运行前继续读取原回执；无需再次点击同一句核对按钮。URL 参数本身不能授权自动核对，标记过期、身份不符或缺少原副本时维持正常恢复流程。恢复成功后清除确认标记，原暂存副本继续保留。

旧页面在离开前仍暂停模拟和新作业；没有清空存档、猜测成功、重复发奖或把未确认请求当作已完成。原先的继续作业、明确取消所见作业和已确认后返回入口保持可用。

## 夜间规划

居民处于休息时间，或世界没有提供可执行目的时，不再发送空目的模型请求。服务端独立复核同样的可执行条件，在没有候选时返回明确的 schedule skip，不占用模型预算。清醒且具备合法目的的居民仍使用 DeepSeek Flash；自动请求间隔和管家手动对话维持原规则。

## 验证与边界

- 两画风的独立 LAN 测试挂起真实的服务端进度读取，验证等待期间可重新进入、自动继续原核对、资源与回执不变、原副本未被新页面覆盖，返回后背包可用。
- 折纸案例还通过独立测试日志模拟旧写入已被确认的情况，验证新页面加载到服务端进度后仍保留最初的暂存副本。
- Codex 内部浏览器使用独立虚构测试岛验证相同等待路径，实际点击链接回岛并打开、关闭背包；没有读取用户原页面或真实存档。
- 既有取消回执丢失、取消身份核对、延迟导航和连续刷新测试继续保留。夜间双画风验证使用明确的初始夜间时钟夹具；不冒充自然运行或真人验收。
- [回岛证据](verification/v216/recovery-reentry.json)；[夜间规划证据](verification/v216/night-planning.json)。

本次没有确认用户原页面卡在哪个阶段；已覆盖等待请求无出口及嵌入浏览器导航被取消这两种恢复路径。托管 Windows 慢渲染下的居民顺序作业超时仍在另行定位，不能由本次恢复测试推断为已修好。
