# V328 · 手动管家委托的保存检查点

## 原因与边界

V327 的 Windows 原居民三步任务中，像素版在手动分工登记 30 秒门失败，plan_batch 请求在门失败后才发出；折纸版原三步任务通过。产物完整性已核对。慢保存与后台居民请求同时存在，不能把这次失败说成完成回执恢复失败，也没有证据证明全部托管耗时的根因。

进一步检查发现：聊天在请求管家之前先等普通保存检查点；它排在未开始的后台作业之后，因此后面的手动批量登记优先级无法帮助前面的等待。独立原生 Worker／HTTP／磁盘夹具，两画风均复现原 5 秒检查点准入失败。

本候选仅给用户主动寄出委托时的检查点本地优先级。它能越过未开始的后台任务，但不能越过进行中的正式事务或更早的显式检查点。后续任务仍不能越过该检查点；原 FIFO、公平轮转、待核对／导入／替换保护和小岛身份核对保留。模型输入及服务端请求不携带该优先级。没有调整 12 秒请求、30 秒登记、120／240 秒工作或 150 秒游客道路时限。
