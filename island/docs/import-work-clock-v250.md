# V250 · 导入预览与低帧率分工

## 导入确认不会被旧保存回调覆盖

原 Windows 检查的两套画风都在等待导入确认按钮时失败。实际文件已读入、服务端当前进度也已核对，但较晚完成的“立即保存”回调重新打开存档页面，覆盖了新的导入意图。

现在选择备份文件就建立新的弹窗操作归属，文件解析和预览沿用该归属；旧保存回调不能重画页面。解析或预览失败时仍显示错误并返回可操作的存档页。没有自动确认导入，也没有跳过签名、预览绑定、版本和原编号恢复检查。

通过延迟真实保存的页面回调、同时等待真实导入核对来复现：原6例中2例失败，修复后6例通过，包含丢失导入／恢复答复后的原编号续接、旧页面封闭、资源与身份保留、重复返回入口。

## 已获准的农活按可见时间完成

低帧率下，20秒获准动作原来使用每帧最多0.15秒的普通规则步长，工具可能挥动很久才提交交付。现在仅已取得对应服务端许可的 NPC 动作使用有上限的可见时间步，并要求许可答复后的完整单调计时持续时间；隐藏帧不能补完成，提交后仍由原服务端回执决定产出。

作物成长、需求衰减、经营结算和900秒有效日继续使用原时钟；未经许可的本地动作不会通过此入口发放物品。服务端最低作业时间、任务依赖、唯一交付和排班检查保留。 隐藏或暂停时，待确认动作不能落入本地完成分支；既有晚间交班用例使用明确的单调时钟和真实 NPC 许可字段，保留一次完成、无取消、客户端不发物品的检查。

- 双画风分别在两组实际 RAF 延迟下完成三步物资分工、中途刷新和空浏览器恢复，均取得3笔唯一实际交付。较重一组测得约1.8–2.4FPS；首项分别约25.5／32.2秒，其余两项共约168.7／159.7秒，保留原120／240秒预算，世界时钟文件未修改。
