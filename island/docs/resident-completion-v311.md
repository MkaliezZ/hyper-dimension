# V311 · 已确认居民作业的结束响应恢复

Windows 商品货架定向诊断中，两种画风的商品图像均已通过检查，折纸风完成购买与刷新。像素风随后停在等待合格买家：服务端已有两名游客正在体验其他设施，前端却被一条居民结束请求的传输超时挡住，游客结束命令还未实际发送。共享命令日志进入待核对状态，因此后续到港及经营停止。不是直接增加游客轮换期限来处理。

现在，SaveClient 只把当次尝试之前已经从服务端确认的居民租约身份传给传输层。若居民结束请求的原 12 秒 fetch 超时，租约类型、NPC 身份、请求号、存档世代及序号全部匹配，才在原 250 毫秒间隔后重读一次同一请求。重读保留原字节、版本及身份；每次 fetch 仍为原 12 秒，没有第三次自动尝试。

只有格式相似的输入、没有已确认租约、租约身份不符、取消、玩家作业、现实任务、普通连接丢失和明确 HTTP 拒绝，都继续保留原有处理。持续超时仍进入核对。服务端已有的唯一回执、资源预留、作业时间及收益计算保持原样，不在客户端提前发放收益。

新增原生夹具使用真实 SaveClient Worker、居民及游客控制器、HTTP SaveStore 与磁盘。旧版本在双画风中均复现锁住；候选在双画风中均恢复：先等待真实 20 秒居民作业，再暂留服务端已经提交的第一次结束响应，直到原 12 秒超时。此时服务端已有两份木料，前端仍为零；一次相同重读后得到唯一回执，后续游客控制器可继续。磁盘重开后再次读取同一回执，木料与回执数量都不增加。该夹具是最小浏览器页面，不宣称验证了完整地图的人物演出。

新增边界检查覆盖 Worker 与后备路径、一次重读上限、已确认租约身份、尝试后才修改租约不能补授权、非目标路由及拒绝响应。完整货架、游客轮换和成交检查继续保留原断言与期限，并加入三系统的结束响应专项检查。

Intel Mac 的定向检查还发现，采集手账沿用了收藏册的界面标记；普通信息刷新会让收藏册绘制器误接管采集弹窗。现在采集手账及其背景暂停使用独立标记，收藏册的绘制器与样式保持原样。旧版本两种画风均复现误替换，候选均通过刷新、采集地点切换、奇观／成就查看及返回采集的原生页面检查。原有采集检查与期限保持原样。

这两项修复的完整托管矩阵及当前交付包尚未确认。[机器可读验证范围](verification-v311.json)。

最终代码在 Node 22.13.0 与 25.8.1 各通过完整默认检查 1614 项，无失败或跳过；原有双画风采集动作检查也通过。托管结果仍按实际完成状态单独记录。
