# V151 · 会客地图操作提示与缓存打开计时

## 地图点击

正常移动请求保存原编号后，轮询可能在回包前返回；旧渲染把在途请求显示成“操作待核对”，导致提示短暂出现、地图下移。现在恢复卡片只在没有在途请求且结果仍待确认时显示；开始/结束动作更新轮询epoch，动作前的旧回包不覆盖最新视图。

[双画风原生回归](verification/v151/native-navigation.json) 使用实际地图鼠标点击，故意延迟轮询与移动响应，验证0闪现、地图位置不跳动。随后丢失实际服务器响应，重试仍使用相同请求编号且不会重复操作。账号与数据为隔离夹具，未接触用户存档。

[V150 Mac Intel流水线](https://github.com/MkaliezZ/hyper-dimension/actions/runs/37978326500) 在缓存打开的墙钟断言失败：计时原来从调用Playwright locator.click前开始，到下一次等待返回，包含动作可点击等待、驱动通信、客户端渲染。像素记录1342ms，折纸超过1500ms；旧失败保留，不声称已证明纯粹测试噪声。

V151分开记录cachedOpenWallMs和浏览器内cachedOpenMs。后一项从真实click事件timeStamp开始，到两个动画帧后展馆tab仍可见；保留1500ms门槛，不改变游戏速度/时钟、不禁用画面或降低视觉质量。本机像素50.3ms（驱动墙钟139ms）、折纸159.7ms（墙钟260ms）。[完整UI回归](verification/v151/native-lobby.json) 还覆盖503身份重试、同档切换/刷新、主题鼠标、草稿保留、桌面/窄屏以及600次/主题同快照NPC朝向。

Intel Mac的实际点击到绘制仍以本次提交CI结果判断；三平台CI不代表实体Mac/真人验收。若真实计时超限，继续修复渲染，不把旧失败改成成功。
