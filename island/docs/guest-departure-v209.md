# V209 · 访客返回会客厅的短暂失败恢复

## 观察与复现

托管 Windows 任务 `116856905028` 已通过恢复回岛测试，随后在访客点击“回会客厅”后等待出行面板超时。保留了该次日志、访客截图和报告；原报告没有退出请求的 HTTP 状态，不能据此断言托管现场一定收到 `lan_busy`。

原客户端仅对移动作重试。隔离测试在访客退出时返回一次 `503 lan_busy`，稳定复现同一停留现象和原有 30 秒面板超时：访客仍在房间，退出请求保留为待核对操作。本机无故障注入的两画风出行基线通过。

## 修正

将用户明确发起的 `room_leave` 纳入有限重试：复用已经持久化的请求编号、房间编号及原版本，最多再试两次。服务端已完成退出而响应丢失时，按同一请求重放原回执，不发起第二次退出。身份错误和房间版本冲突仍直接交给原错误恢复流程，不修改版本强行退出；持续失败仍保留原请求。

没有改动创建房间、聊天、现实工作或其他操作的重试行为。

## 验证与边界

- 新原生回归先返回一次服务忙碌，再实际完成退出并丢弃响应，最后核对同一请求的服务端回执。两画风均回到会客厅，无待核对退出请求；管家名字、形象、两位同意随行的居民、原岛存档、金币及库存保持正确。
- 两画风仍检查六个随行角色的身份与地图对应、名单冻结、刷新保留和移动端布局。增加退出 HTTP 状态、网络失败和客户端状态诊断，便于继续核对其他原因。
- 相关 27 项单元测试通过，覆盖有限重试、原请求与版本不变、身份和版本拒绝，以及移动、档案锁、身份与共用画风规则。

证据来自同一台 Windows 上的独立虚构账号与浏览器，不是物理多设备或真人验收。托管失败的实际 HTTP 原因仍需新日志确认，不能以本机复现替代托管通过。用户存档、配置、浏览器及已冻结交付包未改动。
