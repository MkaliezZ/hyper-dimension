# Rejected commands and resident idle waits

An explicit HTTP 409 `save_conflict` rejects the original command. Only a complete, bound NPC resident/mining/farming begin may use the independent-progress read below. Manual actions, completion/cancellation, unbound requests and a previously failed explicit read barrier retain their existing stop behavior. The client reads the current document once and uses its existing three-way merge against the acknowledged baseline. Independent edits are preserved; the rejected intent is retained separately and still reports rejection. It is never automatically resubmitted, counted as a receipt or awarded materials. Overlapping edits, an island replacement, an unreadable canonical document and uncertain outcomes retain explicit recovery.

During unrelated persistence waits, a free resident's existing idle backoff advances by bounded visible frame time. This starts no new purpose, model call or work lease and changes no saved state. Normal work-hour, hunger, energy, manual-control and pending-receipt checks still govern the next decision. Granted work retains its real 20-second lease and monotonic acknowledgment gate.

Two Windows hosted failures exposed these paths: an external canonical mine lease left a queued client command globally blocked, and a custom project's next resident step spent much of its idle wait behind unrelated saves. The retained reports are regression evidence, not proof that every possible slow project has the same cause. Candidate local native runs retain the original mining, return, gathering, project, reward, reload and time-budget assertions. A deterministic native IndexedDB/HTTP control proves the explicit stale rejection, independent progress preservation, one original command, no earned materials and preservation of the actual external lease until official cancellation. The new hosted control adds coverage without replacing any existing step.
