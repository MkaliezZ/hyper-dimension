# V299 · Agent 验证分组与贴图上传

Agent 部署入口原先将 package.json 中 `&&` 两侧的测试交给一个 Node 进程。Node 22.13 与 25.8 实际复现：前组故意失败时，后组仍被发现并执行，破坏了原有隔离分组和失败后停止的语义。现在先校验整条命令，只允许明确的 Node 测试文件，再使用参数数组逐组等待；任意组失败即停止。未引入 shell，也没有删除测试。四项新增检查包含真正的子进程、顺序依赖、失败停止、含空格的部署路径和危险命令拒绝。初次嵌套测试夹具继承 Node 内部上下文的失败记录保留，修正夹具后重新验证。

Windows 上 Node 22.13 与25.8分别通过1499项规则检查，分组为1485和14项。最低版本首次验证因私有探针将可执行文件改名为node22.exe，导致四项只枚举官方node.exe的旧进程识别检查失败；保留该失败，将同一官方二进制恢复原始文件名后，仅重验未通过的14项，全部通过。原始采集流程完成真实开工许可、动作、被暂扣的无关居民回执、唯一收获结算及重开，两种画风均通过。Intel Mac托管环境仍出现开工许可等待超时；本次仅补充步骤／HTTP时间与稀疏存档状态，不放宽原15秒设置、网络或完成预算，尚未宣称该失败已解决。
