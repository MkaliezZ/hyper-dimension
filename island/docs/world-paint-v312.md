# V312 · 持续存档时的小岛绘制保底

上一提交的 Windows 检查发现，衣橱选择确认并关闭后，八次 RAF 回调只有五次真正绘制小岛，没有达到原有六次门槛。原存档调度仅要求跳帧后下一帧绘制，持续复制时理论上可只绘制四次；现在小岛渲染入口每次让出一帧后，保留三次绘制机会。普通绘制的任意八次回调至少六次可绘制；弹窗主动保留背景时仍按其原有规则处理。

原有存档调度入口保持兼容，100 毫秒后备释放、Worker、权威回执、工作时长与收益规则保持原样。新增检查覆盖连续等待、重叠复制与丢失 RAF 后的释放；原衣橱、采集与存档锁检查的源码、断言及期限保持不变。

原衣橱检查在本机的修复前一次运行本身通过，因此不把它称为本地复现了托管失败；连续等待复制的边界检查确实证明旧策略只留四次绘制。候选通过双画风的原衣橱检查，以及二倍 CPU 节流下的正常和延迟三秒观察采集检查。Windows 存档锁失败停在采集地点选项丢失；V311 的弹窗归属修复后，原检查在双画风均完成三次注入拒绝、唯一回执和空浏览器恢复。

完整托管矩阵及当前交付包仍待确认。[机器可读范围](verification-v312.json)。

最终规则检查在 Node 22.13.0 与 25.8.1 各通过 1617 项，无失败或跳过。托管端的原始绘制、锁竞争及采集检查另行运行，未用本地结果代替托管通过。
