# V292 · 活动版本冲突的刷新等待

## 修改

同一岛屿已有活动刷新请求时，新的调用等待该请求的同一个 Promise，再执行原有的一次版本冲突重试。收起或更换岛屿上下文后，旧刷新结果不会替换新上下文。请求日志、原编号核对、服务端资金和物资校验、准备时间及挑战品质保持原规则。

## 证据与范围

实际活动 UI 在原生浏览器组件中遇到明确标记的 HTTP 协议夹具：后台刷新仍在进行，第一次结束操作收到确定的版本冲突。旧版的重试版本为1→1，双风格都失败；修复后等待实际刷新回包，再按1→2重试，两例通过。没有增加重试次数、延长原检查时限或修改命令结果。该组件使用模拟活动协议，不代替真实经营结算。

36项既有活动、随行工作、经济账簿、IO与重启规则通过，无失败、取消或跳过。经济账簿每风格10天使用已声明的初始库存和时间夹具，不能当作真人长线平衡验收。最近完整默认规则是V291的1470项，不冒充当前V292完整重跑。

原V291模块的四岛折纸流程完成了三位访客的实际挑战（品质均100），随后在两次版本冲突和核对按钮重绘处失败，未结算成功；失败记录保留。加入本次修改的完整四岛流程正在执行，仍保留原10秒完整居民、原50秒实际挑战、真实Flash/Hermes、物资与岛币守恒、原编号重放、评分、重启与回岛检查。没有宣称完整交付、Mac实机、物理多设备或真人验收。
