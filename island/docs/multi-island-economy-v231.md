# V231 · 四岛联动与组合账目核对

## 四岛联动

两套主岛画风分别运行四个独立账户，原岛使用混合画风。每位岛主携带自己的管家及两位已同意的居民，共 12 位随行人物；身份和原岛来源不混淆。通过服务端道路移动、标准 A2A 接口、明确的本人执行、付费共同活动、三个来宾的挑战与评分、重启续接、唯一结算及返岛保存。

模型受控的完整流程与相关协议、随行、招聘伙伴、试作和中断恢复共 33 项检查通过。另一次完整流程使用真实 Hermes / DeepSeek Flash：每套画风 11 轮，共 22 轮管家运行。持久记录核对了原账户执行端、前后轮次关联和已完成状态。活动四个钱包合计只减少 8 岛币场地费，奖励来自主办方预算；交付物资守恒，结束后预留清空。

这些是同一台 Windows 上的隔离账户与运行时。初始物资、时间推进与挑战输入为显式夹具；真实模型运行不能替代实体四设备、真人交互手感、全部活动或通用跨岛供应链验收。居民交谈、招聘伙伴与客岛试作由相关规则流程覆盖，不能称作本轮新增了完整通用协作能力。

## 同一座岛的组合账目

已完成两套画风各 10 个游戏日的核对，五类派对各举办两次，同时结算实际游客服务、十次招聘工资、两次升级、维护及日常开销。每次正式响应均核对物资事件、现金账本、非负余额与库存，重放不重复付钱，结束后使用新的存档服务读取磁盘结果。

初始为已进展岛屿：140 岛币、大部分物品各 100 件，缺少的初始木料与灯笼走正式任务生产。预置商品不向游客售卖。像素岛最终 146 岛币，折纸岛 145 岛币；十天中支付升级 245、维护 116、工资 80、日常费用 720 岛币，未产生欠付。这是账目组合检查，不能据此宣称从零成长、全部订单与专精、真人耗时或长期经济已经验收完成。30 日延长检查单独记录，不与本次通过结果混为一谈。

## 可复现入口

```sh
npm run test:multi-island-integration
npm run test:combined-economy
```

真实模型检查需操作者明确设置私有 `DEEPSEEK_API_KEY`、`HD_QA_REAL_A2A=1` 和独立 `HD_QA_OUT`，并准备部署指南规定的 Hermes/Python 运行时。它会产生真实调用费用；默认入口使用受控回复。密钥和运行目录不进入源码包。

首次运行旧随行／试作测试时，发现未创建结果目录，以及旧试作夹具缺少现行灯笼的石英、蜂蜡与纤维；这些夹具已修正，原业务断言和资金校验保留。更长组合检查曾在预算内未跑完，测试驱动已减少重复读取不变磁盘快照；实际写入、账目断言与原时间预算保持。

课程与练习册加入成品主动上架、留用量、实际游客成交和费用核对；[新玩家与 OPC 任务卡](acceptance-session-v231.md)和空白结果表已准备。尚未填写真人结果，也未把自动验证计入 5–8 位新玩家人数。
