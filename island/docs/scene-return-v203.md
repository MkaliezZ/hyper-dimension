# 室内操作与室外返回位置

`state.player` 保存主岛上的室外返回位置。农田、矿洞和功能建筑中的角色坐标属于当前场景，采集回执、制作和自动保存不能把这些坐标写进主岛位置。

V202 的完整从零流程暴露了实际问题：折纸矿洞里完成采矿后保存了 `(500, 240)`，选采集蜂蜡时把这个室内位置当作室外起点。该点无法接上折纸主岛道路，页面只提示“暂时无法走到那里”，没有发出新的采集请求。使用原失败演示账户的隔离副本可以重复此问题；像素地图上的部分同名坐标碰巧可行走，因而掩盖了错误。

修正后仅在主岛场景更新室外位置。返回主岛时也会校正历史无效位置，使旧档能重新接上可行走区域，不清空进度或物资。

原生回归 `npm run test:scene-return` 覆盖双画风：历史坐标恢复、实际敲矿及回执、矿洞转林地采蜂蜡、步行到农田入口、实际锄地及回执、农田转林地采纤维、刷新后继续采木材。测试使用独立虚构存档、关闭模型请求，不能替代真人体验或全流程验收。

## 保存手账时的版本竞争

慢速环境下，准备操作回执所需的后台暂存会让出执行时间。此前这个阶段尚未阻止自动保存，定时保存可能先写入新版本，随后本页的操作便以旧版本被拒绝，出现仿佛来自另一窗口的冲突。现于准备回执前锁定发送顺序，准备失败时释放；实际操作、材料与去重规则不变。

`tests/v203-save-command.test.mjs` 在回执准备阶段插入真实客户端自动保存调用。旧实现稳定触发版本冲突，修正后自动保存等待，操作只提交一次，期间的本地导航修改仍保留。该回归覆盖保存时序；macOS Intel 的托管实测结果单独记录。

居民的 16 户住所另有独立绘制的内景、碰撞和家具动线，见[逐户设计](residence-interiors-v191.md)。室内小活动继续沿用同一身份和存档，不另建画风进度。
