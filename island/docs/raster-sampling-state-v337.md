# V337 · 减少建筑绘制的 Canvas 状态恢复

四个同时运行的地图中，原生诊断记录到会客馆绘制后的 `CanvasRenderingContext2D.restore()` 单次耗时约 6.4 秒。该函数只临时修改两项图像采样设置，却为每次建筑绘制保存并恢复完整的 Canvas 状态。

现在只保存并在 `finally` 中恢复 `imageSmoothingEnabled` 与 `imageSmoothingQuality`。变换、裁切、透明度与合成状态留在调用者原来的上下文中；原图、GPU 素材重建、裁切和尺寸、像素风与折纸风的采样设置保持原样。绘制异常仍向上传递。

## 验证边界

三项规则检查覆盖两种画风的原始参数、采样和调用者状态，以及绘制异常后的恢复。原生浏览器完成 42 组预热后的逐像素候选对照和 42 组原实现自对照，差异均为零。原实现的生产建筑冷启动首帧在一组相机下自身也有差异，已单独记录；本次没有把该差异归因为候选修复，也没有声称修复冷启动画面。

另有 47 项私有组合候选的相关规则通过，不能并入本次公开默认测试数量。完整四地图组合仍在第四地图 GPU 端点检查失败，未降低断言。本次只公开已独立核对的采样状态修改，其他 UI、海面和 Worker 传输候选继续隔离。完整联机 A2A／活动、新包、新视频及真人／OPC 验收尚待完成。见[机器可读记录](verification-v337.json)。
