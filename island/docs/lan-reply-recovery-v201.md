# 会客厅请求丢失回包的验证

V200 的 Windows 托管会客厅任务在 `APIRequestContext.post` 创建房间时收到 `ECONNRESET`。这次日志明确给出了传输错误；此前缺少 HTTP 正文的失败不能据此追认为同一根因。

原生测试使用的 `postLanFixture` 对连接重置最多重试两次，保持同一请求编号和相同内容。仅明确的繁忙或限流 HTTP 回复进入原有有界等待；身份、参数和未知错误立即失败。没有改变游戏的鉴权、判定或超时门槛。

新的真实 HTTP 故障测试在服务端持久化建房之后丢弃首次回包。客户端恢复后获得原房间的重放回执，两次接收的内容完全一致。另一个测试确认 401、403、400 和未知 503 都只发送一次。两项规则和双画风会客厅原生回归在本机通过。新的托管跨平台结果继续单独检查。

测试使用临时端口、虚构账号与私有临时数据，不调用模型、不读取用户存档。相关入口为 `tests/v201-lan-request.test.mjs` 和 `tests/v148-lobby-browser.mjs`。
