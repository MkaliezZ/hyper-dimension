# V254 · 短暂写入失败后的原任务续做

Windows 暂时占用存档文件时，原子替换和独占锁获取现在最多等待合计2.5秒，保留同一个临时文件、目标文件和锁所有权。持续拒绝仍会报错；不会删除原存档来绕过占用。

游戏存档的持久化动作收到明确的503临时写入错误时，间隔250／750毫秒重试原命令，最多重试两次。编码后的请求、版本、纪元、序号和客户端编号全部保持原样。服务端已经完成但回复丢失时，也只重放原回执。此策略不涉及管家现实工作请求。权限错误、版本冲突、未知服务错误不会被自动接纳；持续失败仍保留原恢复记录，后续不同动作不能插队。

旧代码在9项新增规则中失败4项，双画风原生组件均在首个临时回复处失败。修复后关联17项、完整1335项规则通过。实际Windows文件共享测试覆盖超过旧680毫秒窗口的1200毫秒占用，以及3500毫秒持续占用时原存档字节保持不变。四处旧规则仅同步精确重试次数，原错误、权限、数据保留和单次结算断言保留。

原生组件在服务端实际提交后注入两次503回复，再以相同请求取得原许可，完成真实20秒动作。双画风分别只得到2份木材、0岛币；空浏览器和独立磁盘实例重开、回执重放均一致。这是明确的隔离组件及故障注入验证，不代表真人、完整活动链或物理多设备验收。
