# 管家工作续接 · V82

## 继续一项工作

管家的 Hermes 回复下方会显示“继续这项工作”。点击后，输入区显示当前选择和“仅用普通对话”按钮。寄出下一条消息时，会带入这项工作此前真实保存的对话及工具结果；普通新对话只使用最近的聊天文本。

先检查新消息中的目标和文件路径。管家继续编辑时仍应读取当前文件，不能把旧工具结果当成当前文件内容。选择会话会把此前读取的内容一起发送给配置的 DeepSeek Flash。

原岛入口在“管家”；联机时可从“随行对话与成果”或随行管家入口继续。发送和关闭按钮保持可达，说明与输入区可以单独滚动。

## 会话如何保存

每个管家运行工作区使用自己的 Hermes 原生 state.db。里面保存原生消息、工具调用及结果、运行信息和招聘父子关系。手动对话、岛内巡查、招聘和 A2A 的记录均可以备份；只有当前账号、当前小岛、当前画风下已确认完成的手动工作可以显式续聊。

自动巡查不会加载手动文档上下文，也不会额外提高模型调用频率。模型仍固定为 deepseek-flash。

升级前的聊天和工作成果保留原样。没有原生会话记录的旧回复不会出现续接按钮，可以新开一条委托。

## 回复中断时

若实际文件已经修改，但模型或服务没有给出确认完成的回复，先查看文档成果与实际执行记录。未确认或失败的原生会话不允许直接续接，系统不会自动重做其中的文档操作。

联机丢失提交响应时，客户端保留原委托编号及会话选择。重新打开后先核对服务端已登记的结果，不会另建一个相同任务。

## 备份与移动目录

关闭本项目的所有运行端后，按“完整数据备份”指南执行 data:backup、data:verify、data:restore 或 data:recover。单岛进度备份不能代替完整管家工作区备份。

完整迁移保留历史消息原文、工具调用编号和父子关联；只把运行工作目录重新指向恢复后的目录。恢复后的真实操作仍以新工作区的文件为准。损坏的会话库会阻止完整备份或启动该管家，不会悄悄修补原始数据。

源代码的 Node 最低版本为 22.13.0；离线包固定提供 Node 24.19.0。原生会话备份使用 [Node 官方 SQLite API](https://nodejs.org/api/sqlite.html)，该模块从 22.13.0 起无需实验开关。

## 本地复验

运行 hd.cmd run test:native-sessions，验证真实 Hermes、实际工具、完整迁移与双画风界面。测试使用独立工作区及本地供应商响应，不读取用户文档，也不调用外部模型；通过不等于真实课堂、长时游戏或多设备验收完成。
