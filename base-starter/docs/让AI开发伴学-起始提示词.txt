让 AI 开发自己的伴学：可复制提示词
对应底座 v0.3.2｜学员说明修订版 r2｜2026-10-23

使用方法：在 AI 编程助手中打开完整解压的工程文件夹。复制对应的“开始复制”到“结束复制”之间的内容。把【】替换成你的真实信息；不知道的写“待定”。不要把口令、模型密钥或真实学习者隐私写进提示词。
这些提示词是执行要求，不是已经完成的测试证据。需要助手具有本地文件编辑和终端能力；没有时让它明确说明，并提供给你执行的文件与命令。

提示词一：首次开发，从默认工程到自己的伴学
----------开始复制----------
请在当前打开的独立 base 源码开发包中，直接开发我的伴学，不要只写方案。开发过程不需要连接任何 MCP。

我的应用名称：【名称，待定可先给建议】
服务对象与使用场景：【谁在什么情况下学习】
第一项学习目标：【学习后能完成什么具体行为】
资料位置与使用权限：【工程内文件/本机文件路径；自编、授权或待核验】
学习者提交的成果：【一段回答/一个数值/一份文字作品】
评价依据：【人工评价要点/明确答案/量规；不确定写待定】
最终交付形态：【网页（默认）/ MCP / 网页与MCP都要】
仅选择MCP时填写最终调用它的客户端：【客户端名称；未定可稍后确定】

先读根目录 AGENTS.md、00-学员使用说明.txt、README.md，以及 docs/开发指南.md、docs/通用教学规则与修改入口.md、docs/通用教学接口参考.md，再检查实际代码。未选择交付形态时，按网页开发，不先研究MCP客户端配置。
如果缺少会影响第一项活动的必要信息，集中问我；不影响开发的普通技术选择由你处理。不要收集学校和电话，不要虚构教材来源、分值或已核验结论。

请按顺序执行：
1. 检查环境并运行默认示例与基础自检。说明实际执行结果；遇到安装错误先修复。使用合成学习者和独立测试数据，不覆盖已有实例，不结束无关进程。
2. 用几句话确定第一项活动：目标、资料、成果、评价依据、反馈后如何修订。范围只做一个可用闭环。
3. 主要修改 src/base/app/ 下的配置、资料、生成提示、活动准备、评价、可选档案和下一步策略。普通函数可完成的，不加插件系统、业务ID注册、多租户或工作流引擎。需要改核心时说明理由并补相应回归。
4. 真正替换任务与评价内容，不只改名称。先用现有 text 人工反馈或 numeric 数值等值判定；若新增自动评价，给出教学依据，并增加正例、反例和边界测试。格式通过、提交完成、已评阅和分数都不能自动等同于达标。
5. 同步更新 app/acceptance.json。修改评价算法时更新 assessment_version；重启后用新活动验证。不要拿旧活动检验新配置。
6. 跑 check.ps1、check.ps1 -Business、verify.ps1 以及相关 pytest。实际检查网页中的创建、学习链接提交、反馈、查看、修订和记录保留。若没有浏览器控制能力，完成可执行验证，明确把页面人工核对留给我，不冒充已点击。
7. 选择网页时，完成网页验收和源码打包即可，不安装可选MCP依赖，不研究客户端接入。只有明确选择MCP或两者时，才在业务通过后增加产品MCP接口验收：安装 requirements-mcp.lock、运行 verify_mcp.py，并按需要接入目标客户端。MCP是最终产品的一种接口，不是开发底座的前置连接。

交付：可运行工程、我的业务示例、修改文件与原因、运行命令、合成验收记录、测试结果和未验证项。仅选择MCP时另附实际客户端接入状态；网页项目对此标不适用。失败不得标为通过，未做真人试用不得声称真人可用或教学有效。任何资料和反馈记录都不要带管理口令、完整访问码或其他人的隐私。
----------结束复制----------

提示词二：补充或调整业务，不重建整个项目
----------开始复制----------
继续修改当前伴学工程。
本次要调整的学习目标或规则：【具体变化】
资料或例子：【位置与来源状态】
我希望看到的正确表现：【例子】
我希望能识别的问题表现：【例子】

先检查已有实现，再提出最小修改并直接完成。优先修改 src/base/app 的对应文件，同步更新业务验收样例及必要的正反例测试。通用权限、同名隔离、发布快照与记录保留沿用底座，确需调整再说明原因。
通用教学约定改 teaching.json；学科档案改 profile.py；下一步建议改 strategy.py；新的活动准备改 activities.py；评价改 assessment.py。新增配置键不会自动生效，必须检查读取路径、页面或函数是否实际使用它。不要把所有业务逻辑塞进提示词。
先保留现有数据；变更后重启并创建新活动。运行业务检查与相关回归，说明本次改了什么、具体结果和未支持边界。
----------结束复制----------

提示词三（可选）：把开发完成的伴学作为 MCP 提供给 AI 客户端
只有最终形态选择 MCP 或两者时才复制这一段；网页伴学直接跳到提示词四。
----------开始复制----------
请把当前工程作为本机 stdio MCP 服务接入【实际客户端名称】。这不是桥接另一个伴学服务。
本工程绝对路径：【路径】
网页实际地址：【例如 http://127.0.0.1:8766】
网页实际数据目录的绝对路径：【路径，与 start.ps1 -DataPath 一致】

先确认业务检查已通过。使用工程 .venv 的 Python 安装 requirements-mcp.lock，执行 scripts/verify_mcp.py。它是协议自检，不能冒充实际客户端接入。

服务参数：command 是本工程 .venv/Scripts/python.exe 的绝对路径；args 是 ["-m", "base.mcp"]；cwd 是工程根目录（客户端支持时设置）；env.PYTHONPATH 是本工程 src 绝对路径；env.BASE_DATA 与网页使用同一绝对路径；env.PYTHONUTF8="1"。
查明这个客户端当前支持的配置方式，先检查并备份已有配置，再增加本服务，保留其他服务。路径空格正确转义，不输出已有密钥。若无法操作客户端，交付可复制的准确配置和剩余人工步骤，并把“真实客户端接入”标为未测。

接入后在实际客户端发现全部10项工具；执行 get_context，读取实际资料与教学要求，生成一项原创草稿，调用 check_activity，再让我核对并明确发布；不要仅凭 valid=true 声称内容已审定。
使用合成学习者发布一项活动，必要时先 save_learner，后续复用返回的身份，不按姓名合并。把 student_path 与上述网页地址拼接，完成浏览器提交、list_records 读取本次记录、record_feedback、学习者查看与修订、get_growth 和 plan_next。操作串由你生成，超时只用相同串与相同内容重试，避免重复发布。
保留每一步的结果摘要与使用的数据目录，不泄露口令或完整访问码。列明真实客户端验证、协议脚本验证、页面人工操作分别完成了什么。该 MCP 属于可信维护者入口，不能提供给学习者当作普通登录。
----------结束复制----------

提示词四：验收并打包我自己的伴学
----------开始复制----------
请按 docs/伴学开发-验收清单.txt 验收当前伴学，沿用我选择的交付形态；没有明确选择时按网页验收。先读取实际代码和数据边界，再执行可执行检查；逐项标记通过、失败、未测或不适用，不适用说明理由。保留命令、退出码、结果位置及内容质量待确认项。
检查学习目标、资料、任务、评价与下一步确实属于我的应用；正反例不能只复用默认内容。网页项目不要求MCP，MCP整组标不适用；选择MCP时才分别记录真实stdio和实际客户端接入。不能用单元测试代替全部验收。浏览器或所需客户端未操作的明确留空。真实学习者试用和教学效果单独列出。

完成后生成一个新的源码 ZIP：根目录直接有 README.md、AGENTS.md、src、scripts、docs、tests、examples、requirements.lock、requirements-mcp.lock 和 LICENSE，让另一位使用者完整解压后能 setup 与启动。
整理我的应用说明、开发起始提示词、修改入口、评价依据、运行命令、验收结果、已知限制；仅交付MCP时另附MCP配置参数。沿用的 base 说明注明底座版本，另写本应用名称和版本，不能冒充通用底座发布。
从干净源码文件清单打包，排除 data、.venv、.git、缓存、私有备份、口令、凭据、真实学习者信息和无分发授权的材料。不要直接压缩整个正在运行的工程。保留本机私有数据；不通过删除它们来制造干净包。
解压成新目录核对文件、运行必要检查，确认新实例不会继承我的数据。提供 ZIP、SHA256、文件数、验收报告与未完成项；未通过项目不能写成全部验收通过。
----------结束复制----------

提示词五：出现失败时，让 AI 修好再复验
----------开始复制----------
当前伴学出现问题：【现象与复现步骤】
命令或页面：【内容，不含口令】
错误摘要：【保留错误信息，删除隐私与访问码】
期望行为：【具体表现】

请读取相关配置和代码，实际复现，定位原因后做最小修复。保留失败条件、原因、修改文件和修复后证据，不能只给排查建议或把失败检查删掉。新增业务变化同步更新验收样例和正反例，通用修复跑相关底座回归。
保留已有数据；需要备份先停止自己的写入服务。不要重置实例身份、删除整库、结束无关进程或弱化权限来让测试通过。
修复后重跑失败步骤和必要回归，给出通过项与仍未测项。若缺少必须由我确认的信息，清楚指出缺什么；能独立继续的工作先完成。
----------结束复制----------
