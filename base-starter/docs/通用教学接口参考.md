# v0.3 通用教学接口参考

所有管理接口需维护者Cookie；学习者不能调用。MCP是本机可信维护者入口，不给学习者或未经授权的第三方调用。内部ID由底座生成，网页通过选择档案处理，开发学员无需设计或手填业务ID。

## 新增HTTP接口

| 接口 | 输入 | 输出/约束 |
|---|---|---|
| POST /api/learners | name，profile可选，learner_id可选，request_key可选 | 新档案；或明确更新既有ID；不按同名合并 |
| POST /api/tasks | 原字段，新增可选learner_id | 复用已有档案，称呼须与当前档案一致；返回instance_id与task_version摘要回执 |
| GET /api/growth/{learner_id} | 无 | growth和plan；事件仅限该学习者，不含访问口令 |
| POST /api/tasks/{task_id}/state | state=active/paused/archived | 暂停、恢复、归档；归档不可重开 |
| POST /api/feedback/{submission_id} | 原字段与可选scores，新增judgement、request_key | judgement为空/needs_revision/meets_criteria；返回评阅身份、评价版本、confirmed状态及时间 |
| POST /api/transfer/{submission_id} | context：新情境及条件；independent必须为true | 先有明确达标评价，再由维护者确认独立完成；相同核验内容重试不重复记事件 |

GET /api/manage增加learners、instance_id、teaching与check，供维护者预览通用约定和待核验提醒。学习者读取原/api/learn/{token}，增加state、公开目标/成果和来源简表；没有档案管理权限。提交结果包含review_history（仅本活动），可追溯原评阅。

创建、提交、反馈和档案修改若需超时恢复，使用相同request_key和同样内容；内容变化用新串。feedback和profile的串在各自操作类型内实例级唯一；创建串也是实例级，提交串只需在活动内唯一。网页自动生成，无需学习者输入。没有传串的管理调用不保证重复请求只写一次。

reviewer_id标识本实例的维护者身份，不是已完成实名验证的个人账号；review_state=confirmed表示该维护者入口确认了评价，不等于另有第二位评阅者复核。需要多人复核时增加独立身份和授权，不修改称呼冒充。

无效输入400，未授权403，不存在404。暂停/归档阻止新提交但允许同一操作串读取既有提交回执；归档保留历史只读。重新启用学习应向原档案发布新活动。

## MCP对应工具（10项）

get_context、check_activity、create_activity、list_records、record_feedback、save_learner、get_growth、plan_next、set_activity_state、verify_transfer。

create_activity新增可选learner_id；record_feedback新增scores、judgement和request_key；save_learner参数与HTTP相同，其余与上表语义一致。check_activity返回valid、warnings、semantic_quality_verified=false：提醒不是自动审题通过证明。

生成由客户端Agent完成。学科MCP工具可调用相同Store与app函数，不另建数据逻辑。来源、档案、作品和反馈有私有信息，禁止将list_records或get_context完整输出当公共日志。

app/assessment.py的evaluate_submission(activity, answer)至少返回status（pending或reviewed）、correct（true/false/null）、comment与next_step。它不能只返回一个分数。Store补充评价版本与状态；人工反馈另存评阅历史。若新增学科自动判定，仍需验证错例与边界；不能凭Agent自述就确认独立完成。

## 最短调用示例（Python业务函数）

```python
from base.core import Store
from base.app.activities import prepare_activity
from base.teaching import check_activity

service = Store('data/my-test')
person = service.save_learner('合成学习者', {'goal': '能用依据解释一个观点'}, request_key='profile-1')
draft = prepare_activity()
check_activity(draft)  # valid只表示程序校验；仍需人工核对内容。
task = service.create(person['name'], draft, 'publish-1', person['id'])
submission = service.submit(task['token'], '观点、依据和下一步行动', 'submission-1')
service.feedback(submission['id'], '观点明确；请补充材料中的具体依据。', '补证据后再提交。', judgement='needs_revision', request_key='feedback-1')
service.next_plan(person['id'])
service.growth(person['id'])
```

不要打印task、口令或完整学习链接。此例使用合成数据，只验证函数闭环。

## 兼容与恢复

0.2.x数据库首次打开时只新增表与state列，不改已有活动、访问码和learner_id；历史同名档案不会推断合并。旧档案初始为空，可由维护者补充。升级前停止服务并备份；保留原程序副本，需要回退时恢复升级前备份，不在新库上直接运行旧程序。

备份/恢复是本工程的数据归档，不是任意第三方数据导入协议。只在本机Windows/Python3.11实测；公网、跨平台、跨实例HTTP、多用户负载等须另验。
