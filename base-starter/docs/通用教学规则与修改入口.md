# 通用教学规则与修改入口

base提供可运行的教学起点，不预装各学科的教学真理。先改普通文件，只有明确的业务需求才改代码。既不要求填完全部档案，也不要求每次学习走完全部步骤。

## 先看这三个入口

| 入口（工程内） | 用途 | 修改方式 |
|---|---|---|
| src/base/app/teaching.json | 通用教学约定、反馈参考、维护者/学习者的显示称呼 | 改普通JSON；称呼不会改变权限 |
| src/base/app/profile.py | 学习档案与学科扩展字段的类型、长度和约束 | 在SubjectFields添加Pydantic字段；无需注册 |
| src/base/app/strategy.py | 根据档案与证据建议下一步 | 改plan_next(profile, growth)普通函数 |

具体活动仍编辑config.json、knowledge/material.txt、prompts/activity.txt、assessment.py与acceptance.json。不要给每个学科增加domain-id、活动包注册或流程定义语言。

## 通用规则：底座会执行什么，哪些需要人判断

1. 活动说明目标、提交成果、评价依据和下一步。新示例已填写goal和deliverable；兼容旧活动时缺少这两项会提醒，不会让旧链接失效。必填字段、类型、长度、来源状态与评分配置由代码校验。
2. 文字作品默认待人工反馈。段落齐全、字数达标、提交成功都不能自动证明内容正确或能力达标。结构检查只是文字匹配与字符计数。
3. 评价允许无分数、无唯一答案。量规得分只在配置了rubric后可选填写；“已评阅”与“达标”分开，只有维护者明确填写judgement才记为本次作品达标/需修订。numeric仅判断数值等值，不推定解题过程合格。
4. 反馈应结合本次作品，说明已有表现、差距与可执行下一步。不评价人格。代码强制反馈与下一步非空；反馈是否具体、公允仍由人审阅，不能声称语义已被机器保证。
5. 修订新增提交，不覆盖初稿；重新评价保留评阅历史。暂停阻止新提交，恢复后可继续；归档为只读，继续学习须新建活动。
6. 完成、达标、独立迁移分别记录。独立迁移须有已明确达标的作品，并由维护者填写新情境与独立完成条件；服务端记录人工核验，不自动判断是否真的未获帮助。
7. 来源版本、摘要、抽取状态和核验状态分开。读取本地文字只证明可读取。标为已核验须保留摘要、核验者与时间；绑定material.txt的摘要发生变化会回到待核验。
8. 同名不自动合并；已有学习者明确选择原档案才能跨活动复用。实例身份和业务数据保存在自己的数据目录。复制干净源码会产生新实例，恢复备份延续原实例。

## 十类能力的当前落点

| 能力 | 首版已有 | 留给具体产品的扩展 |
|---|---|---|
| 身份与归属 | 稳定学习者ID、实例ID、同名隔离、跨活动选择同一档案；维护者与持活动链接的学习者两组权限 | 多教师组织、监护人只读、班级/机构关系与独立账号认证 |
| 档案与路径 | 可选目标、已有经验、阶段、时间、资料、进度备注；Pydantic扩展Schema；普通策略函数 | 多目标前置图、复杂排课与路径可视化 |
| 活动生命周期 | 发布、执行、提交、反馈、修订、人工再验证、暂停/恢复/归档 | 诊断/计划可用活动和档案表达；分支由普通业务函数创建后续活动，不提供流程引擎 |
| 一致性与恢复 | 不可变活动参数快照、摘要版本回执、创建/提交/反馈/档案的可选操作串、重试冲突拒绝、持久化、事件记录、备份恢复 | 完整历史代码回放、分布式任务恢复、并发编辑自动合并 |
| 成果与评价 | 文字答案、作品/过程/观察说明；无分数反馈、量规得分、明确达标判定、评阅者/版本/状态、评阅历史 | 文件/音视频上传、等级量尺与其他专用评价结构；等级当前可写入文字反馈 |
| 成长与迁移 | 可追溯学习事件，四类证据计数，人工迁移核验，plan_next接口 | 学科掌握度公式、推荐算法、复杂复习调度 |
| 资源与来源 | 文件引用、页码/片段位置、资料版本、sha256、抽取与人工核验状态 | PDF/OCR、全教材检索、文件授权校验；元数据不是外部来源真实性认证 |
| MCP与网页 | 两入口共用Store；档案、活动、反馈、成长、计划、状态与迁移核验；学习者在网页交作品 | 远程MCP、公网部署、复杂路径编辑与文件上传 |
| 业务开发入口 | app普通文件、函数参数和输出示例、配置样例、业务验收样例、正反例测试 | 仅开发实际需要的领域逻辑；不需插件包或注册表 |
| 分发与体验 | 可运行默认示例、数值/项目/待填模板、配置修改脚本、自检、HTTP/MCP验证、备份导出与恢复、故障说明 | 自动升级合并、通用跨产品数据导入、所有平台的一键部署 |

这些是同一份开发包的能力说明，不是要求学员先选择或安装十个模块。

## 角色称呼与授权边界

teaching.roles只有maintainer和learner。可把maintainer显示为教师、导师、教练，把learner显示为学员或学习者。服务端权限不因文字改变：维护者可管理本实例；学习链接只可查看和提交该活动及其历史。

独立学习者可维护自己的独立实例。监护人如果只应查看特定学习者，需要开发额外的身份、归属关系和只读授权；不要把管理口令交给监护人再称作“只读角色”。本版不伪装成已完成多角色RBAC。

## 档案示例与扩展Schema

基础档案各项均可省略，默认空值：

```json
{
  "goal": "能用材料解释一个观点",
  "prior_experience": "已读过一篇短文",
  "stage": "入门",
  "schedule": "每周两次，每次二十分钟",
  "resources": ["自编阅读材料第一段"],
  "progress_note": "先收集一次初稿",
  "extensions": {}
}
```

学科信息不要塞到core：例如在app/profile.py的SubjectFields内增加 `preferred_topic: str = Field(default='', max_length=200)`，然后extensions即可接收该字段。未知字段会被拒绝；`LearningProfile.model_json_schema()`可取得实际Schema。字段默认值、约束及对应网页输入也由开发者按业务修改。示例不要求学校、电话、年龄、年级或考试日期。

profile接口提交的是完整档案对象；更新已有档案时，省略profile表示保留，传入对象表示按该对象和默认值替换。它不是自动合并补丁接口；多人同时编辑档案暂不提供乐观锁，应由单一维护者操作。

## 活动与来源示例

config新增字段：

```json
{
  "goal": "能把资料中的建议转化成一个行动",
  "deliverable": "一个要点、一个行动、一次执行观察",
  "assessment_version": "1",
  "sources": [{
    "title": "自编材料",
    "file": "knowledge/material.txt",
    "locator": "全文；也可写页码与片段位置",
    "version": "1",
    "extraction_status": "readable",
    "verification_status": "unverified"
  }]
}
```

只绑定knowledge/material.txt时，prepare_activity计算文件字节sha256并记录可读取状态。不读取其他来源路径，也不自动下载外部资料。其他文件或外部引用的摘要、页码与状态由开发者或核验者提供。

核验者检查内容后，在config的该来源加入sha256、verified_by、verified_at，并把verification_status改为verified；必须对应所核验的实际版本。摘要变化时自动取消原核验标记。公开页仅显示标题、位置、版本与状态，不发送本机路径、完整片段或核验者信息。

修改评价算法时递增assessment_version，重启并新建活动。参数快照不能冻结历史Python代码；本版不保证旧任务以后提交仍用旧代码。旧结果保留当时记录的版本，不会自动复算。

## 成长计数与下一步

- encountered：已向该学习者发布的活动数量，不能解释为已阅读。
- completed：已有提交的活动数量，不能解释为合格完成。
- meets_criteria：每个活动最新提交中，维护者明确判为达标的数量。
- independent_transfer：具有人工迁移核验，且对应作品当前仍明确达标的不同提交数；不等于永久掌握。
- pending_submissions/needs_revision：未归档活动的最新提交待评/需修订数量。

策略只给建议，不自动发布、跳级或替人确认达标。默认建议按待评、修订、换情境验证和开始小目标等情况生成。想加诊断、复习或阶段目标，在strategy.py与activities.py写普通函数；不要预建所有学科的路线图。

## 第一次改版的最低验收

只选一个目标、一段资料、一种成果。改完后跑check.ps1 -Business、verify.ps1与pytest；测试正确/不完整作品，人工检查评价依据，再完成一次反馈与修订。需要MCP时额外安装可选依赖并跑scripts/verify_mcp.py。它验证真实stdio与进程内学习者HTTP联动，不验证公网MCP或浏览器点击。

结构检查、满分合成测试和Agent成功复做都不能替代真人学员试教或教学效果验收。
