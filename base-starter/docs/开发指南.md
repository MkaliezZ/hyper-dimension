# 学员开发指南

## 第一个改版

1. 修改src/base/app/config.json中的name、activity_title、instructions、criteria、next_step。
2. 修改knowledge/material.txt，替换成一小段自编或有权使用的资料。私有资料不要随工程分发。
3. 修改prompts/activity.txt，写清真实生成时应遵守的教学要求。
4. 重启服务，重新创建学习活动，用新链接提交并反馈。做到内容、任务要求或评价方法发生变化，才算业务改版。

## 配置与代码

config.json为UTF-8 JSON。name是应用名；activity_title是活动标题；instructions是提交要求；criteria是公开评价依据；next_step是完成后的建议；mode为text或numeric。numeric还需expected，例如字符串"1/2"。expected不会发送给学习者。text没有自动教学评分，维护者通过网页填写反馈。

activities.py的prepare_activity读取当前配置与资料，返回活动对象。assessment.py中validate_activity检查结构，evaluate_submission做业务评价。新增语文阅读、职业项目等可先用text与人工反馈；新增自动判定时在assessment.py实现，不需动数据库。

活动对象包括上述字段及material（资料文字）。普通字段必填，最长20000字。页面提交是文字；作品文件上传、图形、语音和复杂评分尚未实现。

快照保存资料和规则参数，反馈有修订历史；修改评价代码会影响旧任务未来的新提交，不保证完整历史代码回放。发布后若改变评价算法，应新建活动并在应用说明中说明版本。

当前默认页面不单独展示config中的next_step。numeric自动反馈会使用它；text活动的最终下一步由维护者在反馈表单填写。若活动开始前就需要告诉学习者下一步，请在instructions中明确要求，或按自己的产品需要修改页面。不要仅修改未被页面使用的字段便宣称体验已生效。

可以在assessment.py增加段落、字数等结构提示；提示仍标为pending，不把格式满足直接当作内容质量或能力达标。

## 数值与项目示例

examples/numeric/config.json与material.txt演示数值练习；复制其内容到app的相应文件即可，或自己编写。支持整数、小数、分数，不支持带单位、表达式求值或CAS。

examples/project演示成人项目。评分依据在criteria中，维护者人工填写反馈和下一步。项目样例不要求年龄、年级、考试或总分。

## 备份与恢复

先Ctrl+C停止服务，避免备份时有写入。运行.venv/Scripts/python.exe scripts/backup.py backup 目标.zip。包含data和app，备份有管理凭据，应私下保存。

恢复到全新目录：运行.venv/Scripts/python.exe scripts/backup.py restore 备份.zip 新目录。检查恢复出的data与app后，在新的工程副本中放回相应位置。恢复备份延续原实例身份；若创建独立新实例，复制源码即可，不复制data。尚无自动升级迁移。

## 检查与边界

check.ps1用临时数据库验证建档、提交、人工反馈和重启读取。tests/test_base.py还覆盖并发重复提交、访问隔离和数值快照。示例通过不等于真实学员教学有效。

做新业务时，再用一份合成作品检查公开资料、提交要求、评价依据和反馈是否真正对应；不能只看check通过。需要pytest时先设置 `$env:PYTHONPATH=(Join-Path (Get-Location) 'src')`，再运行 `.venv/Scripts/python.exe -m pytest -q`。

隔离验证数据：先设置同样的PYTHONPATH，再运行 `.venv/Scripts/python.exe -m base --port 8766 --data data/test-run`。start.ps1默认固定使用data/base；需要隔离目录时用上述模块入口。测试后停止自己的服务，保留数据以备核查；分发使用干净源码包，不包含data和.venv。

若编写自动化验证脚本：口令只在脚本内部读取，不打印/api/manage或/api/tasks的完整响应，因为它们含学习访问码。网页可直接完成开发验证，以下HTTP摘要仅供需要自动化的开发者：
- POST /api/login：对象token，验证后设置维护者Cookie。
- GET /api/manage：维护者预览、活动和提交；需要Cookie。
- POST /api/tasks：learner、可选draft与request_key；需要Cookie。
- GET /api/learn/{token}：读取该学习活动与记录。
- POST /api/learn/{token}：answer、request_key，提交该活动。
- POST /api/feedback/{submission_id}：comment、next_step；需要维护者Cookie。
- 400表示输入不符，403表示权限或请求来源不符，404表示记录不存在。创建和提交重试沿用相同request_key，修改内容时使用新操作串。学习者界面会自动处理这些操作串，不要求手填。

当前首测Windows、本机HTTP；其他系统、共享局域网、公网、并发多人规模需分别验收。不要将localhost链接当作可从其他设备打开的地址。

## 给AI编程Agent的起始提示

先读README、AGENTS.md和开发指南，跑通默认示例。我要做【服务对象与学习任务】的伴学，资料在【位置】，学习者应交【成果】，完成标准为【依据】。优先修改app配置、资料、提示词和评价代码，完成一次创建活动、提交、反馈与下一步；不要增加插件、ID配置或平台注册。确需改核心时说明理由并做回归。最后交付实际运行证据、修改说明与未验证项。

## 可选产品接口：MCP（学员开发不需要）

这一节不是安装、开发或验证自己伴学的前置步骤。不使用时直接略过。仅当你开发的产品确实需要向Agent提供MCP接口时，再安装可选依赖：`.venv/Scripts/python.exe -m pip install -r requirements-mcp.lock`。

先执行setup。让支持stdio MCP的客户端启动本工程.venv/Scripts/python.exe，参数为-m base.mcp，环境变量PYTHONPATH为本工程src的绝对路径、BASE_DATA为data/base的绝对路径，工作目录为工程根目录。

这相当于维护者访问，仅给你自己的可信Agent使用。它有get_context、check_activity、create_activity、list_records和record_feedback工具。create_activity是明确的发布动作，传learner、draft和request_key（客户端生成的唯一操作串）。发布前确认内容并check；超时后使用相同操作串和相同内容恢复，或list_records检查，不要盲目新建。

get_context返回当前资料、提示词和活动样例。让Agent据此生成草稿，check_activity检查后再明确发布。返回student_path是相对路径，结合网页实际可访问地址使用。工具检查成功不证明内容或评价正确。MCP没有模型API密钥，生成由你的客户端完成。
