A. 工程能在新目录独立运行
[ ] 完整解压后目录直接包含 README、src、scripts、docs、tests 与依赖锁，能找到学员说明和复制提示词。
    证据：文件清单、新目录路径。
[ ] Python 3.11+ 环境执行 setup.ps1 成功；依赖安装失败没有被忽略。启动使用本工程解释器。
    证据：命令、退出码、环境版本摘要。
[ ] start.ps1 启动成功，浏览器实际可打开；端口冲突会换端口，未结束无关服务。
    证据：页面人工确认；只记无访问码的根地址。
[ ] 新源码副本不带其他实例的档案、提交、口令或访问码；本地已有工程数据保留。
    证据：干净包清单、新实例记录数量或脱敏结果。

B. 已经是自己的伴学，而非只换名称
[ ] 写清服务对象、一个可观察目标、资料、学习成果、评价依据和反馈后的行动。
    证据：应用说明与一项完整活动。
[ ] 名称、资料、任务与评价确实对应本业务，AI 实际修改了对应文件。
    证据：修改清单、src/base/app 中的配置与函数。
[ ] 资料是自编或有权使用；标明来源、版本和核验状态，不以“读取成功”替代人工核验。
    证据：来源表；标为 verified 时有实际依据、哈希及核验记录。
[ ] 公开评价依据足以指导学习者修改；分值/量规有业务依据，不是 AI 临时编造的权威标准。
    证据：评价依据、不同质量的作品样例与评阅说明。
[ ] 自动评价（若有）有正确、错误及边界样例，能说明不支持什么；未做语义判定的文字作品仍进入人工反馈。
    证据：业务正反例测试；只有人工评价时写明该方式。

C. 学习闭环真实可用
[ ] 维护者能预览内容并创建活动，学习者链接能看到目标、资料、要求和评价依据。
[ ] 学习者能提交；维护者能找到对应作品、写具体反馈和下一步；学习者刷新后能看到。
[ ] 学习者能依反馈修订再提交，前一次作品和评阅历史仍保留。
[ ] 关闭自己的服务后重启，同一数据目录的记录仍可读取。
[ ] 同一学习者复用原档案可连续学习；同名的两个合成学习者分别建档且记录不混淆。
[ ] 发布后的旧活动保留原内容快照；更改配置并重启后新建活动才使用新内容。算法变化另有评价版本与新活动。
    以上证据：合成活动、提交与反馈摘要或本机页面核对记录；对外报告不附完整访问链接或私有响应。

D. 通用规则与权限没有被改坏
[ ] 学习者不拿维护者口令；未登录不能调用管理接口；不能通过自己的学习链接读取另一人的活动记录。
    证据：相关回归结果。真实页面/接口未测的另标未测，不能只看页面隐藏按钮。
[ ] 角色称呼变化没有冒充新增授权；若另开发监护人、多人教师等角色，另有权限与隔离验证。
[ ] 暂停阻止新提交，恢复后可继续；归档后保留只读记录，不直接重开归档活动。
[ ] 相同操作串与内容重试不重复创建记录；内容改变不能沿用旧串覆盖。操作串由程序处理。
[ ] 成长记录区分发布接触、提交完成、明确达标和独立迁移。未核验独立完成时不记迁移；没有把总分当通用掌握度。
[ ] 学科扩展字段确实通过 Schema 校验；下一步策略实际使用当前业务信息，输出可执行建议。
    证据：相关测试、界面字段、策略结果。没有新增档案字段时，该扩展项可说明不适用。
[ ] 新增配置字段被对应函数/页面实际读取；修改入口有文档，不只写在 AI 对话里。
