base 学员使用说明
底座版本：v0.3.2｜学员说明修订版 r2：2026-10-23

你拿到的是一套可以独立复制、修改和运行的伴学源码开发包。
你可以让有文件编辑和终端能力的 AI 编程助手，在这套工程上开发自己的学科、职业技能或项目伴学。开发过程不需要连接任何 MCP，不需要 DSH 桥接，也不依赖一个外部伴学平台。

最终交付形态由你选择：
网页（默认）：学习者在网页提交，维护者在网页反馈，直接交付可运行的网页工程。
MCP（可选）：开发完成的伴学向可信 AI 客户端提供工具接口，由客户端生成活动、管理记录或写反馈。
网页与MCP都要：两种入口调用同一业务服务。现有MCP主要负责维护者操作，学习者仍用网页提交；若要完全无网页的MCP产品，需要自己扩展学习者提交入口与权限并另行验收。

如果你还没决定，先做网页。源码中包含可选MCP适配器，不表示必须启用它；只做网页也是完整、有效的开发结果。

“有自己的伴学”至少意味着：有自己的学习目标、资料、活动与评价依据，学习者可以提交，维护者可以反馈，学习者可以修订，记录可以保留。只改应用名称和欢迎词不算完成。

先后顺序：解压并跑通示例 → 让 AI 开发一项自己的学习活动 → 验收网页闭环 → 整理自己的源码开发包。只有明确选择MCP时，才增加MCP接口与目标客户端验收。先做一个可用活动，不要一开始做完整教育平台。

一、包里有什么，先看哪里

本文件：从拿到包到交付自己伴学的操作路线。
docs/让AI开发伴学-起始提示词.txt：可以复制给 AI 的开发、调整、验收与修复提示词；另有可选MCP交付提示词。
docs/伴学开发-验收清单.txt：开发结束后按选择的交付形态逐项核对，保留实际证据。
docs/通用教学规则与修改入口.md：底座已有的通用规则，以及哪些由你扩展。
docs/开发指南.md：配置字段、命令、备份和边界。
docs/通用教学接口参考.md：业务函数、HTTP 与 MCP 的输入输出。
src/base/app/：你主要修改的应用目录。
examples/：blank 空白参考、numeric 数值练习、project 项目作品参考。它们是文件示例，不用安装或注册。
tests/、scripts/：回归测试、安装、启动和验证工具。

这份开发包没有真实学习者数据、管理口令、模型密钥、虚拟环境或教材原书。首次运行会在你的电脑生成自己的实例和数据。每位开发学员复制一份，彼此独立；无需选择 domain-id、activity-id 或插件。

二、开始前，先确定一项小任务

给 AI 说明五件事即可：
1. 服务谁，例如成人学习者、某阶段学生、职业新人。
2. 帮助他完成什么可观察的学习目标。
3. 可以使用哪些自编或有权使用的资料，资料放在哪里。
4. 学习者最后交什么。首版已有输入是文字，也可填数值；上传文件、语音等需要另行开发。
5. 怎样判断做得怎样：人工反馈、明确数值答案，或你认可的评价量规。

例如：“做成人时间管理伴学。读取我提供的一页资料，让学习者提交一份明日计划。按目标清晰、行动具体、时间可执行三项给人工反馈，再让他修订。”这不是学科模板限制，也不要求按年级或考试组织。

没有确定全部信息时，可以先让 AI 提出一个小范围方案，再由你确认真实教学要求；不要让 AI 虚构教材、分值、已核验来源或教学效果。称呼用平时怎么叫，先用合成学习者测试，不必收集学校和电话。

三、解压，在你的电脑跑通默认示例

1. 把 ZIP 完整解压到你自己的工作目录。不要在压缩包内运行，也不要覆盖已有工程的数据。
2. 需要 Python 3.11 或以上，以及可下载依赖的网络。打开解压后的工程文件夹，确认能看到 README.md、src、scripts。
3. 把这个文件夹交给有本地文件和终端能力的 AI 编程助手，复制提示词文件中的“提示词一”。只有对话能力的 AI 不能直接替你修改本机文件；这种情况下，你需要自己保存它提供的文件并执行命令。
4. 在工程根目录的 PowerShell 中运行：

   .\scripts\setup.ps1
   .\scripts\start.ps1

安装完成后启动命令会持续运行，这是服务在等待访问。另开浏览器打开 http://127.0.0.1:8765 。使用启动终端提示位置中的本机管理口令登录；默认位置是 data/base/owner-token.txt。口令用于你自己管理，不能发给学习者。

如果端口被占用，使用 .\scripts\start.ps1 -Port 8766，浏览器也打开 8766。不要关闭不属于本工程的进程。如果系统阻止脚本，可仅对本次命令使用：

   powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup.ps1

其他 ps1 脚本可同样运行。不要修改整机执行策略。需要指定 Python 时使用 setup.ps1 -PythonPath "你的完整python.exe路径"。安装失败先解决错误，不要继续当成安装成功。

5. 完成一次默认演示：维护者预览 → 填写合成称呼并创建活动 → 打开学习链接提交 → 回维护者页刷新并填写具体反馈、下一步 → 学习者刷新、修订后再次提交。默认文字活动先显示待反馈，这是预期行为。
6. 在第二个 PowerShell 窗口运行 .\scripts\check.ps1，确认保存与反馈管线正常。它不修改当前学习记录。停止自己的服务时，在启动终端按 Ctrl+C。

四、让 AI 开发你的伴学

先用提示词一提出目标、范围并开发。需要补充业务要求时用提示词二。要求 AI 实际修改文件、启动、验证，而不是只写一份实施建议。

常用修改入口：
src/base/app/config.json：应用名称、活动目标、成果、提交要求、公开评价依据、下一步；可配置量规与结构提示。
src/base/app/knowledge/material.txt：教学资料正文。只读取资料不代表资料已核验。
src/base/app/prompts/activity.txt：客户端 AI 生成活动时的要求。修改提示词不会自动在后台调用模型。
src/base/app/activities.py：活动准备与提供给 AI 的生成上下文。
src/base/app/assessment.py：活动结构检查和提交后的业务评价。
src/base/app/teaching.json：通用教学约定、角色称呼、反馈参考。
src/base/app/profile.py：可选学习档案与经过 Schema 校验的学科扩展字段。
src/base/app/strategy.py：根据档案和学习证据建议下一步的普通函数。
src/base/app/acceptance.json：你自己业务的最小验收样例，必须跟着改。
src/base/page.html：网页布局、浏览器标签和界面文案的修改入口。配置能完成的先改配置；需要改页面时保留现有权限与安全显示方式，再做浏览器验收。

建议先保留 text 模式与人工反馈，能独立使用后再添加自动评价。已有 numeric 只做整数、小数、分数等值判断，不是通用数学引擎。格式检查不等于内容正确。分数可以为空；“提交过”“已评阅”“明确达标”和“独立迁移”是不同的证据。

不用把十类通用能力全部配置完。先实现一项学习活动，不要求插件系统、领域注册、多角色平台或复杂路径图。普通函数和配置能完成的，直接修改。确需新能力，让 AI 明确改了哪里及新增什么验证。

每次修改后重启服务，用新活动验证。已经发布的活动保留当时资料与规则参数快照；不能用旧链接判断新配置是否生效。评价代码本身没有完整历史回放保障：更改算法时更新 assessment_version 并创建新活动。

五、验收自己的伴学网页

先让 AI 运行以下命令并提供退出码与结果摘要；均在工程根目录执行：

   .\scripts\check.ps1
   .\scripts\check.ps1 -Business
   .\scripts\verify.ps1
   $env:PYTHONPATH = (Join-Path (Get-Location) 'src')
   .\.venv\Scripts\python.exe -m pytest -q

check 验证基础管线；-Business 验证你配置的业务样例；verify 会在随机端口和独立 data/verify 子目录真实启动 HTTP 服务，验证提交、反馈、读取等流程，结果位于本次 result.json。单元测试还需包含你新增规则的正例、反例和边界，不能修改预期值去掩盖失败。

这些脚本使用合成数据。verify 中的满分反馈只验证字段、汇总与保存，不代表该作品真的该得满分；脚本也没有代替浏览器点击或真实学习者试用。最后你自己在页面做一次自己的任务，按验收清单检查内容、交互和修订。

做到这里，只做网页的项目已经可以进入第七部分“交付”，无需安装MCP、查客户端配置或连接任何MCP服务。下面第六部分只供选择了MCP形态的开发者使用。

六、可选：把开发完成的伴学作为 MCP 产品

只有最终选择交付MCP或两种入口时，才执行本部分。MCP是你开发出的产品接口，不是学员使用base开发的前置服务。

1. 安装可选依赖并验证协议：

   .\.venv\Scripts\python.exe -m pip install -r requirements-mcp.lock
   .\.venv\Scripts\python.exe scripts\verify_mcp.py

verify_mcp 使用真实 stdio 协议握手与调用；学习者 HTTP 联动使用进程内 TestClient。它不等于已经接入了你指定的真实 AI 客户端。

2. 用提示词三，让 AI 为你的实际客户端生成配置。服务启动参数如下；路径都换成你解压工程的绝对路径：

   command：工程目录\.venv\Scripts\python.exe
   args：-m base.mcp（两个参数："-m"、"base.mcp"）
   cwd：工程根目录（客户端支持时设置）
   env.PYTHONPATH：工程目录\src
   env.BASE_DATA：你的网页实际使用的数据目录，例如 工程目录\data\base
   env.PYTHONUTF8：1

不同客户端的配置文件位置和写法不同，不要盲目覆盖已有配置。MCP 与网页必须指向同一 BASE_DATA，否则会出现“接通了，却看不到网页记录”。只在终端运行 python -m base.mcp 会等待协议输入，不能凭它未退出就认为 MCP 接入成功。

3. 在真实客户端发现工具，按一次合成任务验证：
   get_context 读取资料、教学约定和生成要求 → AI 准备原创活动草稿 → check_activity 检查 → 你核对内容并明确同意发布 → create_activity 创建活动 → 浏览器学习者提交 → list_records 找到本次提交 → record_feedback 写入评价 → 学习者查看并修订 → get_growth 与 plan_next 读取证据和建议。

重复练习选已有学习者档案。首次需要档案时可用 save_learner；同名不合并，AI 读取底座生成的身份后操作，不要求你手填 ID。超时重试用相同 request_key 和相同内容；内容变化用新操作串，避免盲目重复发布。操作串由 AI 或程序处理。

工具共有 10 项：get_context、check_activity、create_activity、list_records、record_feedback、save_learner、get_growth、plan_next、set_activity_state、verify_transfer。独立迁移需要达标证据和维护者对新情境独立完成的确认，不能仅凭一次得分记录。

MCP 是本机可信维护者入口，能读取私有记录和写评价。不要把它当作学习者账号开放。返回的 student_path 是相对路径，应拼接网页实际地址后给对应学习者。127.0.0.1 链接只在这台电脑可用；局域网、公网、远程 HTTP MCP 和多用户部署需要另做部署与验收，当前包没有自动提供这些能力。

七、交付前留下什么

按 docs/伴学开发-验收清单.txt 逐项记录“通过 / 失败 / 未测 / 不适用”，不适用写理由。先填写交付形态；只做网页时，MCP整组写不适用，不能因为没接MCP而判定网页开发失败。
至少留下：一项自己的完整活动、资料来源与核验状态、评价依据、正确/错误或不同质量的作品样例、一轮反馈修订记录、运行与测试摘要、修改入口说明、未完成事项。若交付 MCP，再提供真实客户端工具发现和往返调用证据。

让 AI 使用提示词四完成验收和源码打包。自己的发布包应包含源码、依赖锁、脚本、示例、测试和说明，保留 LICENSE；不要打包 .venv、data、缓存、口令、模型凭据、真实学习者信息或未获分发授权的教材。新的使用者应解压后重新 setup，生成自己的独立实例。

先停止服务再备份自己的私有记录：
   .\.venv\Scripts\python.exe scripts\backup.py backup 我的私有备份.zip
恢复到全新空目录：
   .\.venv\Scripts\python.exe scripts\backup.py restore 我的私有备份.zip 恢复目录
备份含身份与管理凭据，单独私存；它不属于开发包。外部绝对 DataPath 不在工程 data 内时需另行备份。保留旧工程与备份，不要清空全部 data 来解决问题。

八、遇到问题先查什么

找不到 Python或依赖：检查 Python 3.11+、指定解释器路径、网络；使用工程自己的 .venv 解释器。
网页打不开：查看启动错误，确认端口与浏览器地址相同，换空闲端口。
改了内容没变化：重启自己的服务，确认编辑的是当前工程，再创建新活动。
文字回答一直待反馈：这是默认人工反馈流程；到维护者页评阅，不能直接把 pending 改成“自动达标”。
MCP 能启动却没工具：确认客户端支持 stdio，检查解释器、依赖、参数与绝对路径，读取错误摘要，不把凭据写进报告。
MCP 看不到网页记录：核对双方使用的绝对 BASE_DATA，避免新建第二套数据。
新增档案字段不显示：简单字段可自动生成表单；嵌套对象等复杂结构需要自己开发页面。
测试失败：用提示词五让 AI 按“复现—定位—修复—回归”处理，保存失败原因和未测项，不要只给结论。

最后的边界：工程检查或 AI 独立复做通过，不等于所有学科内容已审定、真实学员一定能独立完成开发，或伴学已经具有教学效果。本次新增说明尚未由真人开发学员独立复做；你的最终验收还需要一位未参与开发的人按说明复做，并让实际目标学习者试用。
