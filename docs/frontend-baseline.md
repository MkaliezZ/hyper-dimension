# 首期前端基线：2D 小岛

首期公开页面和受保护的教师业务页面，以同一工作区中的“超维空间-2D-本地演示”为视觉与交互基线。新前端代码放在本仓库内；不在演示目录上开发另一套业务后端。引入演示代码时保留其 MIT 原作者声明。具体业务内容使用模拟信息起步，随后由教师确认。

## 保留的体验语言

- 首页沿用天空背景与漂浮岛体的双图层、六栋房屋热点、鼠标跟随提示和移动端触控缩放。
- 延续现有侧边栏、页脚三张信息卡、圆角弹窗、奶油底色、青绿色主色与木色文字，不新增完全不同的管理系统视觉。
- 现有配色参考：主色 #2abaaa、深主色 #1f9489、奶油色 #f7f3e7、沙色 #ddd6c0、木色文字 #877358。圆角常用 8、14、20、28 像素；卡片使用轻阴影、顶部主色描边和轻微悬浮反馈。
- 新 tag 用相同尺寸、间距、圆角、悬停和焦点反馈；新信息卡延续图标、眉题、标题、描述、分区、详情和行动按钮的内容层级。
- 教师工作台的列表、表单、报告和口语回听面板沿用这些设计变量，但优先保证可读性、手机操作与键盘可用性。

## 页面信息架构

| 入口 | 公开页或受保护页 | 作用 |
| --- | --- | --- |
| 小岛首页 | 公开 | 教师岛与六栋房屋 |
| 英语体验站 | 公开体验，正式作答需登录 | 简短匿名样题；引导到授权报名 |
| 课程与成果 | 公开 | 课程、服务和已获准公开的案例 |
| 认识老师 | 公开 | 教师介绍及获准资料 |
| 教师工作台 | 登录后 | 班级、教材单元、题库和任务 |
| 学生档案与班级进度 | 教师登录后 | 受限证据、共同里程碑、动态对齐建议、教师确认与个人计划；口语复核后续接入 |
| 我的任务与报告 | 学生/监护人登录后 | 本人作答和经教师预授权策略自动批准或异常人工覆核的反馈 |

已有六栋房子的 ID 与卡片映射参考项目的教师版设计文档；新增页面不得把学生资料直接写入静态 JSON、Astro 构建产物或公开页面源码。若需新增侧栏 tag，应先明确其角色、权限、目标页面和空状态，再按现有组件风格制作图标与卡片。

## 组件对齐点

2D 演示中的 BaseLayout、SideBarMenu、InfoCards、Card、global.css、首页热点配置提供布局与视觉参考。教师业务页面可以抽成共享组件：页面框架、导航项、信息卡、状态徽标、表单区块、证据卡、审批栏和音频播放器。视觉层与 FastAPI 业务 API 分离；页面根据已授权的 API 响应渲染，不用静态内容伪装真实测评状态。

## 资产与公开仓库边界

2D 演示的代码标注 MIT，保留原版权声明后可按该许可复用。其旧图标中有来自外部素材站的资源，不能只凭模板代码的 MIT 声明推断图标也可在本公库重新分发。新增入口按现有形状、色彩和笔触生成原创图标；复用现有图标或图片前核实逐项授权。用户提供或项目生成的岛体、背景与头像也应记录来源，公开入库时附素材说明。当前 web/ 采用重新绘制的 SVG 图标和注明来源的演示素材。

## 开发顺序与验收

1. 在本仓库建立可运行的 Astro 前端，复用获准的 2D 结构、样式和素材，并保留原作者 MIT 声明。
2. 先接入模拟教师数据，做公开小岛和教师/学生受保护页面的导航壳层。
3. 后端 API 就绪后，按任务、证据、复核、班级进度对齐、个人计划、报告逐页接入；教师可查看建议依据、确认或覆盖，学生只看本人计划，未获批准的数据不得进入公开卡片或学生可见区。
4. 同时检查桌面与手机布局、键盘焦点、录音权限失败和空数据状态；与原 2D 演示并排核对风格一致性。

可运行的 2D 基线现位于 web/，其中人物和内容均标为 DEMO。首个教师页面 `/teacher` 已增加原创侧栏图标、模拟班级列表、档案编辑、归档校验与进度对齐建议确认；`/student` 使用同风格页面和原创图标，供模拟学生签写领题与提交，并复用现有色彩、卡片、按钮和布局。页面经 TypeScript/Astro 构建及桌面与手机宽度的模拟数据交互核对；真实认证、教师任务/报告/个人计划、成果发布和学生本人报告/计划读取尚未接入。开发态 `/api` 同源代理仅指向本机模拟 API，静态产物需要部署侧反向代理。
