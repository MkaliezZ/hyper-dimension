## 下一段可验收开发

1. 冻结一位试点教师、班级、共同能力里程碑和已核页教材单元；先建共享教材版本目录、教师绑定与里程碑，核对原书权利、OCR 和页码，再逐步建立获准内容的全文/向量索引。同步固定[动态进度对齐契约](curriculum/dynamic-progress-alignment-v0.1.md)的证据可比性、分组规则和验收样例。
2. 按[身份网关设计](identity-gateway-v0.1.md)建立生产教师/监护人身份、Agent 委托、未成年人模式策略、租户/班级权限、PostgreSQL 迁移、密钥与档案存储保护；再允许处理真实学生。
3. 将本地教师 API 和 MCP 服务接到同一云端业务服务；用已批准读写证据生成个人能力快照和每周班级对齐建议，教师确认后形成分层任务与四周个人计划。完善限额、拒绝/复核、恢复与审计。
4. 在 2D 视觉基线中做教师可编辑档案、策略、班级进度、对齐建议确认、成果发布界面以及学生答题页；公开展示只读取已发布且许可有效的数据，学生只看本人计划。
5. 按[教育 A2A 语义 Profile v1](a2a-education-profile-v1.md)实现服务端权限与幂等，再接学生 Agent 的 A2A Agent Card/端点，使用相同 Schema、身份与授权规则做跨 Agent 兼容测试。

MCP 降低参数格式错误，不能阻止模型选错动作；A2A 解决 Agent 之间的任务传递。敏感操作的最终约束仍在服务端。参见[教师 MCP 与 A2A 业务契约](teacher-mcp-a2a-contract.md)。
