## 下一段最小可验收开发

1. 选定一位模拟/试点教师、一个班级及一册已核页的英语教材，冻结首个读写任务与教师审核人；用 [题目生成流程](../skills/english-assessment/references/item-generation-workflow.md) 产出版本化题包和质量记录。
2. 设计并实现 PostgreSQL 表与迁移：教材证据、蓝图、题目版本、发布决定、作答、评分草稿与教师决定、错因、报告、审计事件。先确保未批准题目和报告不会被学生读取。
3. 实现受控 API 的最短闭环：`draft item → teacher review → publish → submit response → score draft → teacher confirm → report draft → approve`，用模拟学生、无真实隐私的数据验证。
4. 把同一 API 接入 2D 风格的教师卡片入口和学生轻页面，再接教师 Agent 白名单工具。听力/口语按实际媒体和量规准备情况逐步加入；学生 Agent、A2A 和硬件不阻断这个纵向切片。

**当前开发位置：第 0 步的部分契约与内容样板已做，第 1 步只搭了 FastAPI 起点；尚未进入可运行的教师测评闭环。**
