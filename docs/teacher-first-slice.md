# 教师版首个实现切片

目标：一位英语教师、一个班级、一个教材单元，用模拟学生完成“教师授权策略 → Agent 实时出题及答案/量规 → 学生作答 → 自动评分与审批 → 报告归档”的闭环；异常进入教师复核。6—15 岁是架构范围，题库和口语量规逐学段由教师验证。

实时命题、自动评分与审计落库按[运行契约](curriculum/realtime-assessment-and-audit-v0.1.md)实现。题目起草按 [英文题目生成流程](../skills/english-assessment/references/item-generation-workflow.md) 先核验教材与公开试题依据、冻结测评蓝图，再按教师预授权策略实时生成并通过质量门；[当前开发状态](development-status.md)区分已完成的样题设计与尚未实现的业务服务。

## 开发顺序

1. PostgreSQL 数据与迁移：教师、班级、学生、单元目标、教师策略、监护同意记录、题目版本、作答、口语媒体引用、评分版本、自动批准决定、报告、计划、幂等记录和审计。
2. 受控 API：所有查询按租户、岛屿、班级和学生范围授权；未通过教师预授权策略及质量门的草稿不对学生可见。
3. 学生轻入口：听、说、读、写任务；口语音频走受控上传和短期引用。
4. 教师工作台：基于现有 2D 小岛视觉与组件语言，实现教师策略及权重配置、抽样核题、异常复核、报告查询与撤回；建议关联具体证据。
5. 教师 Agent：仅调用白名单工具，Agent 生成题目、答案和量规，并给出评分与报告；服务端按教师策略自动批准合格结果，Agent 不能绕过策略直接改已批准记录。
6. 教师公开小岛：沿用 2D 本地演示的首页、侧栏与卡片风格，只引用已获准公开的内容；真实学生记录保留在受保护页面。新增 tag 使用同风格原创图标。
7. 后续学生 Agent：A2A 适配器把结构化消息映射到同一业务服务；A2A Task ID 关联业务 request_id 和审计 event_id。

## 预留业务操作

- hd.education.plan.read.v1
- hd.education.assignment.read.v1
- hd.education.evidence.submit.v1
- hd.education.feedback.request.v1
- hd.education.teacher_help.request.v1

请求和结果封套的结构见 schemas 目录。服务端必须从已验证凭据和代理授权得出操作人身份；不相信请求正文自报的身份、监护同意或教师授权；开户同意和教师预授权都从服务端记录读取。A2A 只承担传输与任务生命周期，不代替业务审计。

首个基础提交只提供契约和应用起点。具体教学标准、等级阈值与口语量规在试点教师确认教材和单元后版本化，不由 Agent 自行定稿。
