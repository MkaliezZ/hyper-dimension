# 教师版首个实现切片

目标：一位英语教师、一个班级、一个教材单元，用模拟学生完成“目标 → 任务 → 作答/口语 → 草评 → 教师复核 → 报告与计划审批”的闭环。6—15 岁是架构范围，题库和口语量规逐学段由教师验证。

题目起草按 [英文题目生成流程](../skills/english-assessment/references/item-generation-workflow.md) 先核验教材与公开试题依据、冻结测评蓝图，再交教师审核；[当前开发状态](development-status.md)区分已完成的样题设计与尚未实现的业务服务。

## 开发顺序

1. PostgreSQL 数据与迁移：教师、班级、学生、单元目标、题目版本、作答、口语媒体引用、评分版本、报告、计划、监护授权、审批和审计。
2. 受控 API：所有查询按租户、岛屿、班级和学生范围授权；未批准的评分草稿不对学生可见。
3. 学生轻入口：听、说、读、写任务；口语音频走受控上传和短期引用。
4. 教师工作台：基于现有 2D 小岛视觉与组件语言，实现题目审核、回听与复核、报告和计划批准；建议关联具体证据。
5. 教师 Agent：仅调用白名单工具，模型负责草稿，不直接写已批准结果。
6. 教师公开小岛：沿用 2D 本地演示的首页、侧栏与卡片风格，只引用已获准公开的内容；真实学生记录保留在受保护页面。新增 tag 使用同风格原创图标。
7. 后续学生 Agent：A2A 适配器把结构化消息映射到同一业务服务；A2A Task ID 关联业务 request_id 和审计 event_id。

## 预留业务操作

- hd.education.plan.read.v1
- hd.education.assignment.read.v1
- hd.education.evidence.submit.v1
- hd.education.feedback.request.v1
- hd.education.teacher_help.request.v1

请求和结果封套的结构见 schemas 目录。服务端必须从已验证凭据和代理授权得出操作人身份；不相信请求正文自报的身份、监护同意或教师批准。A2A 只承担传输与任务生命周期，不代替业务审计。

首个基础提交只提供契约和应用起点。具体教学标准、等级阈值与口语量规在试点教师确认教材和单元后版本化，不由 Agent 自行定稿。
